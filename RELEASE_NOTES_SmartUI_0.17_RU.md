# Smart UI 0.17 — компактное управление через CLI

Настройки своей ноды доступны короткими командами из приложения: мелодия,
звук, общая и ночная тишина, ADC, уведомления, пины, экран, GPS, радио и подключение.
Инструкция и контракт команд входят в Developer Kit; встроенные страницы
`help` локального companion CLI удалены.

**Дополнение к документации 9 октября:** [доступность команд по каждой плате](https://github.com/YaziAranea/MeshCore/blob/smartui-0.17/docs/CLI_BOARD_MATRIX_RU.md).
Матрица входит также в ZIP помощника и Developer Kit. Уточнено, что `fem.pa`
означает переключаемое усиление, а не питание PA; успешный `get` не доказывает
поддержку изменения. Команды и логика прошивки этим дополнением не изменены.

## Что изменилось

1. **Понятные переключатели.** `set sound on/off` разрешает звук уведомлений,
   `set mute on/off` управляет общей тишиной. `set melody N` сохраняет мелодию,
   `melody N` читает название, `sound preview` прослушивает сохранённый вариант.
   `test` проверяет уведомление с текущими каналами.
2. **Ночная тишина.** `set night_quiet on` включает тишину до утра в местном
   окне 23:30–07:30 при достоверных часах. Ручной mute не снимается ночным режимом.
   `set mute on/off` отменяет ночной режим; приложение перечитывает оба значения.
3. **Быстрые фразы обычным текстом.** `reply set 1 Скоро буду`, `reply get 1`,
   `reply reset 1`. Девять слотов, до 64 байт UTF-8. Сохранение фразы не отправляет
   сообщение в эфир. Пробелы сохраняются; управляющие символы и `|` запрещены.
4. **Переключение подключения.** `get connection`, `set connection ble/usb/wifi`,
   `connection status`. Сначала отправляется ответ, затем меняется режим.
   Для Wi-Fi требуется заранее сохранённая сеть.
5. **Компактный контракт для приложения.** Новые команды обнаруживаются по
   `control=1` в `ui hello`. Кнопки приложения используют `caps` и `schema`,
   отправляют одну команду, затем перечитывают результат. Прежние `ui …`
   и короткие псевдонимы сохранены.
6. **USB Helper 2.4 и SDK.** Новые команды поддержаны Python/JavaScript-клиентами
   и командным полем помощника. Вместо встроенного help — подсказки команд
   и внешняя инструкция. На старой прошивке неподдерживаемые команды не отправляются.
7. **Проверка стека nRF52.** Ветви разбора текстовых фраз и скалярных параметров
   разделены; ARM-проверка учитывает вложенный расход стека. Сервисный `settings`
   получил корректное подключение функций мелодий и мостового звука.

## Примеры

```text
get melody
set melody 18
sound preview
set mute on
set mute off
get adc
get battery
reply set 1 Да, скоро буду
reply get 1
```

`set` обычно сразу сохраняет изменение; отдельная `save` не нужна.
ADC через `preview/apply` и настройка Wi-Fi через `test/save` остаются поэтапными.
При потере ответа переподключитесь и прочитайте состояние: запись могла выполниться.
Автоматически повторять её нельзя.

`sound preview` учитывает общую тишину. Успешный ответ подтверждает запуск
команды, а физический звук зависит от платы, вывода и подключённого излучателя.
Настройки и допустимые пины проверяются через `schema`; номера — Arduino-выводы
своей платы. Не переносите распиновку другой модели.

`set adc VALUE` принимает поправочный коэффициент, не напряжение аккумулятора.
Для замера мультиметром используйте `adc preview MV` в милливольтах, затем
`adc apply TOKEN`. Диапазоны платы, проверки замера и защита записи сохранены.

| Heltec V4.3 OLED R2 | `Heltec_V4.3_UI_0.17-update.bin` / `Heltec_V4.3_UI_0.17-merged.bin` |
| Wireless Paper FULL | `Paper_UI_0.17-update.bin` / `Paper_UI_0.17-merged.bin` |
| Heltec V4 R8 OLED | `Heltec_V4_R8_UI_0.17-update.bin` / `Heltec_V4_R8_UI_0.17-merged.bin` |

UF2 обновляйте поверх, без `FLASH_ERASE`. Для работающей ESP32-ноды с совместимой
разметкой используйте `update.bin` по **0x10000**, без очистки памяти.

**ESP32 `merged.bin` — чистая установка по 0x00000. Он перезаписывает identity,
контакты и настройки даже без Erase Flash.** V4.3 R2 и V4 R8 — разные сборки;
R8 с цветным TFT в комплект не входит.

Скачайте **SmartUI_USB_Helper_2.4.html** или ZIP помощника заново: старый файл
сам не обновится. Для нового CLI нужна и прошивка 0.17. Набор всех плат —
`SmartUI_0.17_all-boards.zip`; SDK — `SmartUI_Developer_Kit_0.17.zip`.
Всего 7 плат, 11 прошивок и 19 файлов. Манифест и SHA-256 связывают файлы
с точным commit исходного кода.

## Совместимость и проверки

База MeshCore **1.17.1 / PowerSaving**, companion-протокол **14**, локальный
CLI **CMD66/RESP29**. Прежние машинные команды и сервисный USB handshake сохранены.
Формат сохранённых настроек не менялся. Контакты, каналы, ключи и сообщения
обслуживаются штатным companion-протоколом. Удалённый CLI через LoRa, старый
API201 и синхронизация событий 0.11 не добавлены.

Wi-Fi/TCP5000 остаётся без отдельной аутентификации/TLS: используйте доверенную
локальную сеть без публикации порта в интернет.

Проверяются сборки семи плат, целостность UF2/BIN и хранилища, CLI, ошибки и откат
записи, ночная тишина, ADC, ARM-фреймы, SDK и интерфейс помощника в браузере.
**Физические платы этим выпуском не испытаны.** Компиляция и симуляция не
подтверждают проводку, звук, аккумулятор, FEM или приём в эфире.

[Предыдущий Smart UI 0.16 сохранён отдельно](https://github.com/YaziAranea/MeshCore/releases/tag/smartui-0.16).
