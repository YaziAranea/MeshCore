# История изменений

Все заметные изменения этого проекта документируются здесь. Стабильная линия `v1.0.0` основана на PS16; `v2.0.0-rc1` переносит тот же пользовательский интерфейс на PS17.

## [SmartUI 0.05](https://github.com/YaziAranea/MeshCore/releases/tag/smartui-0.05) — 2026-09-24

- Выбор одного активного подключения в меню, с сохранением и подтверждением смены режима.
- Bluetooth/USB Serial на всех шести платах; Wi-Fi/TCP дополнительно на V3/V4.3/Paper.
- USB-консоль настройки Wi-Fi: пробное подключение, явное сохранение, пароль без вывода.
- Локальное подтверждение нового TCP-клиента, запрет захвата текущего соединения вторым клиентом.
- Раздельное состояние сессий, ограниченные очереди и обработка частичных Serial/TCP кадров.
- USB не считается подключённым без обмена с приложением; консоль не смешивается с бинарным протоколом.
- Документация: [подключения](docs/CONNECTIONS_0.05_RU.md), [release notes](RELEASE_NOTES_SmartUI_0.05_RU.md).

## [SmartUI 0.04](https://github.com/YaziAranea/MeshCore/releases/tag/smartui-0.04) — 2026-09-23

- Новая короткая нумерация: 0.04, не V4. Шесть прежних плат, без нового отдельного GPS-варианта UF2.
- Опциональный UART/NMEA GPS для ProMicro: автоопределение скорости, выключен по умолчанию, диагностика отсутствия данных, свежесть позиции и ограниченная обработка UART.
- Исправления очереди BLE и напоминаний, идентификация отправителя по ключу, таймеры после переполнения `millis()`.
- Изоляция ADC-предпросмотра от защитной отсечки, проверка сохранения настроек и контактов, безопасное поведение при ошибке сброса.
- Ночное предложение не сбрасывает ввод; обратный перевод часов не считается утром; исправлен срок показа входящего окна Paper.
- Ограниченное ожидание BUSY у Paper, восстановление дисплея, сохранение общей линии питания радио.
- Подготовленный SPIFFS во всех ESP32 merged; аварийный экран не обходит контроль батареи.
- Подробные границы и инструкция: [release notes](RELEASE_NOTES_SmartUI_0.04_RU.md), [ProMicro GPS](docs/PROMICRO_GPS_RU.md).

## [SmartUI V5](https://github.com/YaziAranea/MeshCore/releases/tag/smartui-v5) — 2026-09-19

- Исправление на той же странице V5: nRF52 flash-cache больше не обходит
  `LED платы: ВЫКЛ`. Вызовы `ledOn` для встроенного LED проходят через
  общий выключатель на T114/T096/ProMicro; операции записи данных не меняются.
  Первоначальный V5 исправлял только TX/UI и не закрывал этот источник мигания.
  UF2 нужно скачать заново; внутренний маркер исправленных сборок — `LED2`.

- `LED платы: ВЫКЛ` стал общим запретом для встроенных LED: статус,
  LoRa TX и уведомление на том же штатном GPIO не включают их повторно.
- Встроенный GPIO уведомления подчиняется общему выключателю; отдельный
  внешний LED на другом GPIO сохраняет собственные настройки.
- LoRa TX не считается непрочитанным сообщением: радио продолжает работать,
  отключается только управляемая прошивкой световая индикация передачи.
- Физический индикатор зарядки вне управления MCU не обещано выключать.
- Исправления V4 сохранены: напоминание через 120 секунд от начала серии,
  два проигрывания на nRF52840, mute и сохранённые пользовательские настройки.
- CI проверяет hardware gate и UI/persistence policy LED. Выпуск остаётся
  экспериментальным; успех на каждом физическом экземпляре не заявляется.
- Один публичный Latest-выпуск: шесть плат, девять прошивок, 14 assets.
  V4 и V3 не удаляются и доступны для отката.
- Storage без изменений: V3 merged разрушителен; чистая установка
  V4.3/Paper по-прежнему может дать `STORAGE ERROR`.

[Файлы, изменения и ограничения](RELEASE_NOTES_SmartUI_V5_RU.md).

## [SmartUI V4](https://github.com/YaziAranea/MeshCore/releases/tag/smartui-v4) — 2026-09-18

- На T096/T114/ProMicro nRF52840 восстановлены звуковые напоминания
  о непрочитанном ЛС/упоминании через две минуты от начала предыдущей серии.
- Звуковая серия nRF52840 ограничена ровно двумя проигрываниями мелодии:
  короткий burst-gap не запускает лишнюю серию, повторный callback не перезапускает активную.
  LED-серия ProMicro сохранена, число проигрываний остальных плат не менялось.
- Недопустимый сохранённый GPIO зуммера больше не блокирует fallback
  на штатный допустимый вывод; LED/PWM не сбивает звук на общем GPIO.
- Настройки и выбранные режимы уведомлений не сбрасываются. Для звука
  важных событий нужен режим «Зумер» или «Оба», не «Свет»/«Выкл».
- UI V3 сохранён; заставка — `MeshCore` / `V4`, девять коротких прошивок
  и `SmartUI_V4_all-boards.zip` входят в один выпуск из одного commit.
- Новые программные проверки тайминга/повторов и GPIO входят в CI:
  120 сценариев настоящего C++ и 6262 случая GPIO прошли локально.
  Исправление конкретного ProMicro и стабильность всех плат на железе не заявляются.
- Обычный публичный выпуск отмечается Latest только после проверки 14 assets;
  V3 сохранён для отката. Ограничения V3 merged и STORAGE ERROR V4.3/Paper остались.

[Файлы, изменения и ограничения](RELEASE_NOTES_SmartUI_V4_RU.md).

## [SmartUI V3](https://github.com/YaziAranea/MeshCore/releases/tag/smartui-v3) — 2026-09-17

- Тихий режим на главном экране обозначается только mute-иконкой: слово «ТИХО» убрано.
- Для значка перечёркнутого динамика подготовлены отдельные растры; отключённые
  сигналы в меню обозначены «Выкл», а не «Тихо».
- На заставке — `MeshCore` и короткая версия `V3`, без названия города.
- Сокращены имена девяти прошивок и общего архива `SmartUI_V3_all-boards.zip`.
- Остальные функции, пиктограммы и меню experimental.2 сохранены; радио,
  энергосбережение, калибровка и V3 FS2 не менялись.
- Один публичный экспериментальный выпуск для шести плат, 14 assets;
  beta.2 остаётся Latest. Аппаратная стабильность нового выпуска не заявляется.
- V3 merged остаётся разрушительной чистой установкой, а ограничения
  чистой установки V4.3/Paper не скрываются.

[Файлы, изменения и ограничения](RELEASE_NOTES_SmartUI_V3_RU.md).

## 2.1.0-experimental.1 — Heltec V3 OLED FS2, 2026-09-08

- FS1 не устранила `STORAGE ERROR` на пользовательской V3, несмотря на успешную
  программную проверку образа. Причина отказа на конкретной плате не подтверждена.
- Только для V3 добавлено восстановление запуска. При ошибке mount штатная SPIFFS
  может подготовить раздел автоматически лишь после точного совпадения SHA256
  с известным пустым заводским образом и проверки расположения/размера раздела.
  Стертый FF-раздел, любые другие данные или ошибка чтения этот путь не разрешают.
- В остальных случаях предложено двухэтапное подтверждение кнопкой перед удалением
  ключа identity, контактов и настроек. Отказ/бездействие не форматируют flash.
  Вместо бесконечного `halt()` доступны действия восстановления и выключения.
- В приложении и V3-манифесте ревизия FS2. Merged по-прежнему предназначен для
  осознанной чистой установки и перезаписывает данные даже без Erase Flash;
  update записывает только приложение. Имена файлов и страница Release прежние.
- Успешное аппаратное испытание FS2 пока не заявляется. Остальные пять прошивок
  не меняются; исправление относится только к V3.

## 2.1.0-experimental.1 — Heltec V3 OLED FS1, 2026-09-08

- Исправление V3 для чистой flash: прежний merged не содержал готового SPIFFS,
  поэтому после Erase запуск с `SPIFFS.begin(false)` мог дать `STORAGE ERROR`.
- **Fresh-install merged FS1 содержит отформатированное пустое SPIFFS.**
  Запись по `0x0` заменяет сохранённые identity/настройки **даже без Erase Flash**;
  файл предназначен только для осознанной чистой установки.
- **Обычное обновление — update BIN по `0x10000` без очистки.** Оно не записывает
  файловое хранилище, но само по себе не исправляет пустое SPIFFS после Erase.
- Runtime-автоформатирование не включалось: ошибка чтения не приводит к молчаливому
  стиранию данных. Проверяются маркер FS1, application slice, готовое пустое
  хранилище и контрольные суммы; аппаратное испытание FS1 не заявляется.
- На прежней странице Release обновляются шесть V3-дополнений с прежними именами,
  включая общий архив. Исходные 12 assets пяти плат и тег `00df4872` не меняются.
  Манифест отдельно указывает ревизию FS1 и новый source commit для двух V3 BIN.
- **Известное ограничение:** прежние V4.3/Wireless Paper не пересобраны; после
  Erase пустое SPIFFS на этих целях также может вызвать `STORAGE ERROR`.
  Исправление и файлы V3 на них переносить нельзя.

## [2.1.0-beta.2](https://github.com/YaziAranea/MeshCore/releases/tag/v2.1.0-beta.2) — 2026-09-07

### Интерфейс и напряжение АКБ

- Аптайм перемещён под часы на всех пяти дисплеях и всегда показывает полные часы с минутами (`U 40h05m`), без перехода к дням и без сброса часов на 24.
- На T114 дата сокращена до `дд.мм` и выровнена по строке аптайма; компактные OLED используют часы 2× с отдельной строкой аптайма.
- Wireless Paper выпускается одной сборкой `FULL` с экранной клавиатурой и адресной отправкой; лесной фон убран. Старые WOOD-файлы остаются в прежних релизах для отката.
- Убрано накопительное сглаживание старых кадров для напряжения АКБ. UI получает медиану трёх текущих ADC-измерений с кэшем до одной секунды; пробуждение и калибровка сбрасывают его. E-paper читает текущее напряжение при штатном обновлении, без учащения refresh панели.
- Аварийная отсечка сохраняет независимые измерения, три подтверждения и пороги 3,2/2,7 В.

- Общий читаемый 8×8/12×12 набор пиктограмм на всех пяти платах; различаются звук/mute, дом/офис/завод и письмо/сообщение/заметка.
- Выравнивание значков по видимым bitmap-пикселям букв. Исправлены резерв места mute у батареи и двойной mute T096.
- Нижняя строка T114 больше не обрезается в крупных шрифтах; симуляция проверяет реальные glyph-границы всех 15 шрифтов T096 и 10 шрифтов T114.
- Заставка Wireless Paper работает как в WOOD, но без лесного фона: автопереход, минутное обновление, часы, дата, аптайм и непрочитанные сохранены.

### Публикация

- Выпуск доступен как обычный публичный GitHub Release с пометкой **БЕТА**. Новая страница становится Latest только после проверки полного комплекта из 12 файлов; повторный запуск публикации обновляет ту же страницу тега.
- Имена файлов, встроенные маркеры версии и инструкции обновлены до `2.1.0-beta.2`. Предыдущий `v2.1.0-beta.1` сохранён для отката.

Подробности изменений и проверки — в [примечаниях выпуска](RELEASE_NOTES_v2.1.0-beta.2_RU.md). Компиляция и симуляция не заменяют аппаратных испытаний.

## [2.1.0-beta.1](https://github.com/YaziAranea/MeshCore/releases/tag/v2.1.0-beta.1) — 2026-09-01

### Исправлено

- Добавлена единая проверка длины и формы companion-команд до чтения полей; короткий новый кадр больше не наследует хвост предыдущего.
- Закрыты короткие channel/path/contact кадры, переполнение префикса группового сообщения и зависимость ACK/адресата экранной клавиатуры от перемещаемой записи или позиции списка.
- Настройки, контакты, каналы и identity сохраняются через проверенные `.tmp`/`.bak`; повреждение всех поколений identity больше не маскируется тихим созданием нового адреса.
- ESP32 не форматирует SPIFFS автоматически при ошибке монтирования; перенос во вторичное хранилище удаляет исходник только после проверки размера и CRC32.
- Защита АКБ принимает любое ненулевое измерение как реальное, использует отдельную median-of-three safety-ветку и три последовательных подтверждения. Пороги остаются 3,2 В и 2,7 В.
- RTC различает доверенное и приблизительное время. Удалён ложный seed 2026 года; время контакта не может затереть подтверждённые часы или запустить ночной режим.
- Таймеры UI/АКБ переведены на сравнения, безопасные при переполнении `millis()`; учёт занятого эфира опрашивает радио не чаще 10 раз в секунду и не приписывает глубокий сон приёму.
- Калибровка ADC ограничена безопасным диапазоном платы, отклоняет NaN/переполнение и позволяет восстановить заводской множитель.

### Добавлено и изменено

- Настройка часового пояса `UTC−12:00…UTC+14:00` с шагом 30 минут и сохранением только после подтверждения.
- Компактный аптайм перенесён из меню на экран часов всех пяти поддерживаемых плат.
- Снимок сети для распознавания упоминаний вынесен из стека; повторные вычисления для одного сообщения убраны.
- Phone GPS в публичных профилях остаётся выключен; экспериментальная команда перенесена с занятого соседнего номера на отдельный ID.
- Зависимости релизных целей закреплены точными версиями/commit. Публикация beta выполняется только после общего CI-gate; повторная публикация того же тега обновляет одну страницу и её файлы.
- Companion-конфигурации Heltec T1 переведены с раздувающего UI `-Ofast` на `-Os`, как T096/T114: штатные ExtraFS-разделы сохранены, USB и BLE снова помещаются во flash. T1 остаётся только контрольной, а не релизной платой.

Точные результаты сборки, симуляции, размеры и SHA-256 находятся в [примечаниях выпуска](RELEASE_NOTES_v2.1.0-beta.1_RU.md). Физическая проверка всех пяти плат этим changelog не заявляется.

## [2.1.0-dev.2](https://github.com/YaziAranea/MeshCore/releases/tag/v2.1.0-dev.2) — 2026-08-31

### Исправлено и улучшено

- GPS-страница T114: нижняя строка помещается в физический экран; QA использует реальные 24px глифы компактного font 0 вместо старой 22px модели.

- Компактные OLED-сборки не включают неиспользуемые крупные bitmap-таблицы; действующие шрифты и их метрики сохранены. Старые E213-профили удалены из генератора, поскольку WOOD/FULL их уже не использовали.
- GPIO уведомлений и резонанс зуммера выбираются через черновик с подтверждением. Промежуточное листание не пишет настройки во flash; выход отменяет черновик.
- Поиск упоминаний не выполняет повторное преобразование одного текста. Ручной и автоматический анонсы используют единый путь получения координат.
- Ограничена длина ответа custom vars, чтобы значения сенсоров не выходили за буфер.
- На пяти релизных платах защита АКБ по умолчанию включена: основной порог 3,2 В; при выключении защиты сохраняется нижний порог 2,7 В. Сохранённый выбор пользователя не перезаписывается. Калибровка ADC обязательна для достоверного измерения; аппаратное испытание нового поведения питания не заявляется.
- Документация описывает постоянный BLE PIN, чувствительность `prefs.json`, видимость локальных чатов при физическом доступе и возможную потерю `smart_ui` при откате на stock.
- CI добавляет четыре контрольные сборки общих display-драйверов, не расширяя список плат Release.

Этот выпуск создаётся отдельно; `v2.1.0-dev.1` сохранён для отката. Изменения BLE PIN/часов предыдущего hotfix сохранены. Точные результаты нового выпуска — в [его примечаниях](RELEASE_NOTES_v2.1.0-dev.2_RU.md).

## [2.1.0-dev](https://github.com/YaziAranea/MeshCore/releases/tag/v2.1.0-dev) — 2026-08-22

### Исправлено

- Восстановлен потерянный при переносе PS17 ремонт старого GPIO зуммера. Сохранённый LED/alert pin больше не остаётся tone pin вместо аппаратных D31/D13/D9 на T096/T114/ProMicro; version-marker выполняет ремонт один раз и не стирает последующий ручной выбор общего alert/tone GPIO.
- Исправлен разбор `prefs.json`: ключи SmartUI с цифрами (`tone_8bit`, `favorite_1` и другие) теперь читаются обратно. Раньше файл успешно записывался, но после перезагрузки часть настроек могла остаться со значениями по умолчанию.
- PowerShell-рецепт checksum-манифестов теперь пишет переносы LF, совместимые с `sha256sum -c` в Linux/macOS.
- Если stock PS17 уже создал `prefs.json` без секции `smart_ui`, настройки SmartUI один раз и только один раз дочитываются из сохранённого PS16 `/new_prefs`.
- BLE-синхронизация времени принимает корректное время телефона назад и вперёд в безопасном диапазоне 2024–2040. При исправлении будущего RTC назад также перестраивается внутренний unique-timestamp floor, поэтому сообщения не продолжают уходить с датой из старого будущего.
- Wireless Paper больше не показывает аппаратно невозможные режимы оповещения; три быстрых слота получают рабочий capability-aware fallback вместо дублированного `Оповещения`.
- Предпросмотр коэффициента ADC больше не меняет сохранённую настройку до подтверждения; отмена возвращает рабочее значение.
- T114 и Wireless Paper получили реально изменяемый коэффициент измерения АКБ; на Wireless Paper добавлена задержка стабилизации ADC.

### Добавлено

- Калибровка АКБ/ADC доступна на всех пяти поддерживаемых платах и хранится в `smart_ui.adc`.
- Heltec V4.3 OLED FEM ON: полный SmartUI, аппаратный GPS, управление LNA/FEM, экранная клавиатура и правильные ESP32-S3 BIN-файлы.
- Heltec Wireless Paper: точный 250×122 e-paper UI, кириллица, пять компактных font-profile, защита общей линии GPIO45/VEXT и два профиля:
  - `WOOD` — рекомендуемый, без дорогой для e-paper экранной клавиатуры;
  - `FULL` — клавиатура и target picker, с периодическим полным обновлением против ghosting.
- CI отдельно собирает и проверяет три nRF52 UF2 и три пары ESP32-S3 `freshInstall-merged.bin` / `update.bin`.

### Ограничения

- Это предварительный GitHub Release, а не новый стабильный выпуск. Компиляция и симуляция не заменяют проверку V4.3 и Wireless Paper на реальном железе.
- Wireless Paper V1.0 не заявлен; профиль рассчитан на ревизии с поддерживаемым определением BUSY polarity.
- На V4.3 и Wireless Paper физического зуммера нет: прошивка не назначает выдуманный tone GPIO.

- Аппаратный GPS UI для T096/T114 с состояниями `GPS ON/OFF`.

- Публичная русская документация по платам, управлению, прошивке, сборке, SHA-256, безопасности и экранам.

### Изменено

- Одна общая мелодия заменяет раздельные мелодии ЛС, системы и упоминаний.
- Серия важного уведомления ограничена двумя проигрываниями.
- Настройки сгруппированы; низкоуровневые GPIO и тесты перенесены в `Дополнительно`.
- Длинные строки в многорядных меню статически сокращаются вместо одновременной бегущей строки.
- BLE PIN-страница T096 исчезает после подключения.
- T114 UI проверяется после реального масштабирования логических 128×64 в физические 240×135.
- T096 клавиатура и target picker используют безопасные role-fonts с реальными bitmap-метриками.

### Исправлено

- Окно непрочитанных больше не показывает всю историю каналов.
- Локальное удаление ЛС и поздняя BLE-синхронизация не списывают следующее сообщение дважды.
- Повторный callback не запускает третье проигрывание важной мелодии.
- Важное сообщение не перекрывается ночным запросом и не теряет управление кнопкой.
- ProMicro выходит из сна по пользовательской кнопке D6/GPIO6 без обязательного Reset.
- Убраны две пустые страницы между чатом и настройками.
- Статусы и пиктограммы не должны перекрывать друг друга на целевых геометриях.

### Удалено или отключено

- Phone GPS, поскольку без отдельного phone-side приложения координаты не поступают.
- Экспорт/импорт настроек и выбор профиля из пользовательского экранного меню.
- Ретрансляторы из списка адресатов `Контакты`.
- FakeTec, Heltec V3/V4 и другие платы из области публичного релиза.

### Проверено

- Три публичных PlatformIO environments `v1.0.0` собрались с `SUCCESS`.
- Статический контракт: `31 PASS / 0 FAIL`.
- Точная framebuffer-симуляция: `455 PASS / 0 FAIL`.
- Проверялись UF2 magic values, блоки, адрес старта и маркеры версии.

### Известные ограничения

- Отдельная физическая проверка именно публичной упаковки `v1.0.0` не заявляется.
- T096 близок к пределу flash; публичная сборка `v1.0.0` занимает 96.7% области приложения.
