# SmartUI USB помощник 1.2

Небольшая локальная утилита для SmartUI 0.06-test.1 с обратной совместимостью с 0.06/0.05: настройка Wi-Fi, выбор подключения, свои быстрые фразы и проверка файла прошивки. Показывает версию SmartUI, Core, Build и плату; отключает Wi-Fi-кнопки, если прошивка явно сообщает отсутствие Wi-Fi. Не требует установки Python, драйверов самой утилиты, аккаунта или подключения к интернету. Системный драйвер USB-платы всё равно должен работать.

## Запуск

1. Скачайте `SmartUI_USB_Helper_1.2.zip` из тестового релиза и распакуйте его. Либо скачайте отдельный `SmartUI_USB_Helper_1.2.html`.
2. Откройте HTML-файл в актуальном **Google Chrome или Microsoft Edge на компьютере**: правой кнопкой → «Открыть с помощью». Это интерфейс утилиты, а не файл прошивки. Не загружайте его в веб-флешер.
3. На ноде выберите **Настройки → Подключение → Bluetooth или Wi-Fi**. В режиме USB-компаньона текстовая консоль недоступна.
4. Закройте веб-флешер, PuTTY и другие программы, которые используют COM-порт ноды.
5. Подключите USB-кабель с передачей данных. На **Heltec V3 и Wireless Paper сначала разбудите ноду кнопкой**: USB–UART не сообщает прошивке об открытии порта. Затем нажмите **«Выбрать USB-порт»** и выберите ноду в окне браузера.
6. Дождитесь **«Консоль SmartUI подключена»**. Теперь кнопки доступны.

Страница не открывает порты сама: требуется ваш выбор и разрешение браузера. На мобильных устройствах работа не заявлена. Если браузер или корпоративная политика запрещает USB для локального файла, не отключайте защиту: используйте обычную консоль по документации проекта.

В **SmartUI 0.06** полученные USB-данные удерживают ESP32 бодрствующим **120 секунд**. Мастер настройки Wi-Fi и режим USB-компаньона не дают устройству уснуть. После длительного бездействия V3/Paper снова разбудите кнопкой перед командой. У V4.3 с native USB CDC автоматический сон отключён, как в upstream. Эти уточнения не обещают такой же защиты сна в старой 0.05.

Помощник запрашивает `info` только после точного нового ответа `help`. У совместимой старой консоли 0.05 поля версии и платы остаются пустыми; Wi-Fi-кнопки доступны, потому что возможности платы неизвестны. Некорректный ответ нового `info` не отображается: подключение не подтверждается, реквизиты не передаются. Самоописание прошивки не является криптографической проверкой подлинности устройства.

## Настройка Wi-Fi

Wi-Fi есть на **Heltec V3, V4.3 и Wireless Paper**. На T096, T114 и ProMicro доступны только Bluetooth и USB-компаньон.

1. Введите точное имя сети и пароль. Регистр и пробелы сохраняются; кавычки добавлять не нужно. Сеть — обычная 2,4 ГГц с персональным паролем, не корпоративная сеть и не сеть с веб-авторизацией.
2. Нажмите **«Проверить сеть»**. Пароль исчезнет из поля; помощник последовательно передаст реквизиты по USB, только после запросов проверенной консоли.
3. Дождитесь результата. При неудаче прежние сохранённые данные не заменяются; пароль для повторной попытки нужно ввести заново.
4. При успехе нажмите **«Сохранить сеть»**. Проверка сама по себе ничего не сохраняет.
5. Выберите **Wi-Fi** в блоке режима, если он ещё не выбран. Нажмите **«Обновить состояние»** после подключения к роутеру. После сохранения новое соединение может установиться не мгновенно.
6. В совместимом приложении MeshCore выберите TCP/Wi-Fi, адрес ноды и порт **5000**. Приложение и нода должны находиться в одной локальной сети.
7. Нода принимает первое приложение автоматически, без нажатия кнопки. Второе приложение не вытеснит первое. Используйте только доверенную локальную сеть: отдельного пароля TCP нет, любой имеющий сетевой доступ к ноде может подключиться.

Нужно отменить результат теста — нажмите **«Отменить проверку»**. Если ничего не делать две минуты, прошивка сама отменит незавершённый мастер. Во время активной операции остальные команды заблокированы; можно отключить помощник.

Если помощник прервался во время сохранения, **результат может быть неизвестен**: операция могла уже завершиться на ноде. Переподключитесь и проверьте состояние, не считайте такую ошибку автоматическим откатом.

## Режим USB-компаньона

Кнопка **«USB-компаньон»** переключает саму ноду, а не открывает чат в помощнике. Перед сменой появляется предупреждение. Консоль закрывается, поэтому надёжного текстового подтверждения нет: проверьте режим на экране ноды. Закройте соединение помощника, прежде чем открывать этот порт в приложении.

Для возврата выберите Bluetooth или Wi-Fi кнопками ноды. Одновременно один порт нельзя занимать флешером, помощником и приложением.

## Безопасность и ограничения

### Свои быстрые фразы

1. Подключите сервисную консоль новой прошивки. В блоке «Свои быстрые фразы» нажмите «Прочитать фразы с ноды». Старые 0.05/0.06 не поддерживают редактирование фраз: помощник не отправляет им новые команды.
2. Измените один из девяти слотов. Максимум — 64 байта UTF-8, не символа; счётчик под полем показывает расход. Управляющие символы и повреждённый Unicode не допускаются.
3. Нажмите «Сохранить фразу N». Подтверждение появляется только после ответа ноды и совпавшего чтения слота обратно. Сохраняется именно этот слот; остальные не изменяются.
4. Пустая строка или «Вернуть стандартную» возвращают встроенную фразу. Изменения сохраняются в настройках ноды, не в браузере. На ноде перед отправкой остаётся выбор адресата.

Неподтверждённая запись не означает автоматический откат: при обрыве USB переподключитесь и заново прочитайте фразы. Редактирование не меняет протокол приложения-компаньона и не работает поверх его бинарного USB-потока.

### Восстановление настроек подключения

В новой прошивке при локальном `storage=recovery-required` остаются доступны обновление статуса и повтор безопасной очистки настроек подключения. Кнопка «Повторить очистку хранилища подключения» удаляет сохранённую сеть и возвращает BLE; перед действием есть подтверждение. Другие изменения заблокированы. Внешний quarantine всего хранилища по-прежнему запрещает запись. При выбранном USB и отключённом из-за ошибки companion новая прошивка отдаёт порт сервисной консоли; активный бинарный поток не смешивается с текстом.

### Проверка BIN / UF2 без прошивки

1. Выберите файл прошивки и `RELEASE-MANIFEST.json` из одного релиза либо перетащите оба файла в блок проверки. BIN/UF2 — не больше 32 МиБ; manifest — не больше 2 МиБ.
2. Если нода не подключена или её модель неизвестна, выберите точную плату вручную. При известной подключённой плате несовпадение блокирует положительный результат.
3. Нажмите «Проверить файлы». Проверяются запись манифеста, размер, SHA-256, структура ESP32 BIN/nRF52840 UF2, встроенные метки платы/версии/source commit и различие update/merged. Проверка поддерживает манифест SmartUI schema 2, включая опубликованную 0.06.

**MERGED перезаписывает identity, контакты и настройки даже без Erase.** UPDATE рассчитан на `0x10000` и требует уже установленных совместимых bootloader и таблицы разделов; проверка не определяет их наличие на устройстве. UF2 предназначен только для bootloader указанной nRF52-платы.

Файлы обрабатываются только в браузере. Сетевых запросов и автоматической прошивки нет. SHA-256 подтверждает совпадение с выбранным манифестом, а не подлинность: manifest не подписан. Подходящий файл не является доказательством исправности платы.

### Общие ограничения

- Пароль не отправляется в интернет, не записывается в журнал, localStorage или файлы. Помощник не содержит внешних скриптов, аналитики или сетевых запросов. Это не обещание защиты от вредоносного браузера, расширений, ОС или физического чтения памяти.
- «Показать пароль» отображает его только по вашему запросу. Не показывайте экран посторонним.
- Журнал содержит только заранее подготовленные сообщения помощника. Сырой вывод устройства, имя сети и пароль не выводятся.
- **«Удалить сеть с ноды»** требует отдельного подтверждения и удаляет сохранённые Wi-Fi-реквизиты, но не контакты и сообщения.
- TCP-соединение ноды не защищено TLS. Используйте доверенную сеть; не пробрасывайте порт 5000 в интернет. Сеть без пароля требует отдельной отметки и не рекомендуется.
- Имя сети ограничено 32 байтами UTF-8. Пароль — 8–63 байта либо 64 шестнадцатеричных символа. Переводы строк и управляющие символы запрещены. Имя сети `cancel` зарезервировано консольным мастером прошивки.
- Помощник проверяет формат ответов консоли. Начиная со встроенной 0.06 протокол сообщает версию и плату; протокол 0.05 — нет. Сведения выводятся только текстом, без исполнения HTML; произвольный вывод порта и повреждённые записи отбрасываются. Используйте помощник с SmartUI 0.07, прежними 0.06-test.2, 0.06-test.1, 0.06 или 0.05, а не с произвольными устройствами.
- При открытии USB некоторые платы могут перезагрузиться из-за схемы USB–UART. Дождитесь загрузки и повторите подключение. Помощник не выполняет прошивку, форматирование памяти или автоматический сброс.
- Проверены автоматические сценарии с имитацией USB и интерфейс браузера. Проверка на физической ноде не заявляется.

## Если что-то не получается

**Нет порта:** другой USB-кабель, исправный разъём, системный драйвер платы. **Порт занят:** закройте другие программы. **Консоль не подтверждается:** проверьте режим ноды, версию прошивки и выбранный порт. **Wi-Fi недоступен:** проверьте, что это ESP32-плата. **Нет ответа приложения по Wi-Fi:** нужен клиент с поддержкой TCP, правильный IP и порт 5000; закройте другое подключённое приложение.

Обычная консоль остаётся доступной: [подробная инструкция](https://github.com/YaziAranea/MeshCore/blob/smartui-0.06/docs/CONNECTIONS_0.06_RU.md).

Исходники помощника: каталог `tools/usb-helper` основной ветки репозитория. Лицензия проекта — MIT; текст включён в ZIP. Браузерная основа — [Web Serial API](https://developer.chrome.com/docs/capabilities/serial).

## Проверки для разработчиков

```text
python tools/test_connection_controller.py
python tools/test_quick_reply_storage.py
python tools/test_usb_helper_package.py
node --test tools/usb-helper/test_core.js
node --test tools/usb-helper/test_firmware.js
node --test tools/usb-helper/test_ui.js
```

Последний тест требует Playwright и отдельный Chromium; сам готовый помощник этих зависимостей не требует. Native suite `test_companion_node_prefs` проверяет UTF-8, сохранение/чтение фраз, копирование и старые настройки. Host-модели не заменяют физические испытания flash и USB.
