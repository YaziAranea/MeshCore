# Smart UI 0.22 — управление своей нодой через LoRa

**Ноду в машине или дома теперь можно настроить и перезапустить по радио.**
Нужны две ноды: **нода рядом с телефоном** и **удалённая нода**, которой хотите
управлять. На удалённой должна стоять **SmartUI 0.22**.

## Быстрый запуск

Первую настройку удобнее сделать, пока обе ноды рядом.

1. **Добавьте ноды в контакты друг друга.** Проверьте, что они видят друг друга
   по радио. Приложение должно уметь открывать удалённую консоль контакта;
   названия и расположение этой функции зависят от приложения.
2. **Подключите телефон к удалённой ноде.** В её контактах найдите
   **ноду рядом с телефоном**. Включите у этого контакта **Remote CLI**
   и сохраните. Если такого пункта нет — ниже есть вариант через команду.
   **В oMmesh:** «Настройки» → «Приватность» → «Кто может управлять радио».
   Включите ноду рядом с телефоном и подтвердите «Дать».
3. **Теперь переключите телефон на ноду рядом с телефоном.** Откройте
   **удалённую консоль контакта удалённой ноды**. Обычный чат и локальная
   консоль подключённой ноды для этого не подходят.
   **В oMmesh:** профиль контакта удалённой ноды → «Ещё» → «Консоль радио».
4. **В этой удалённой консоли отправляйте по одной команде:**

| Команда | Что получите |
| --- | --- |
| `ver` | Версию удалённой ноды — сначала проверьте связь этой командой |
| `get battery` | Состояние её питания |
| `set mute on` | Включение общей тишины |
| `get mute` | Проверку результата: `> 1` — тишина включена, `> 0` — выключена |
| `set mute off` | Выключение общей тишины |

Для перезапуска отправьте **`reboot`** там же, в удалённой консоли. Команда
не сохраняет ожидающие изменения: они могут потеряться. Ответ может не прийти,
поскольку нода уже перезапускается. Дождитесь её возвращения и проверьте `ver`;
не отправляйте перезапуск снова только из-за тайм-аута.

**Доступ включается именно на удалённой ноде, в контакте ноды рядом с телефоном.**
Для управления в обратную сторону право нужно выдать отдельно на другой ноде.
Разрешение получать телеметрию само по себе не даёт права управления.
Дополнительный пароль не нужен. Обычный чат отправляет сообщение, а не команду.
Если приложение не предоставляет удалённую консоль, ввод текста в чат её не заменит.

### Если в приложении нет переключателя Remote CLI

Подключитесь **непосредственно к удалённой ноде**. В её контактах откройте
сведения о ноде рядом с телефоном и скопируйте её полный **публичный ключ**
(`Public key`): 64 символа `0–9`, `a–f`. Это **не BLE PIN, не имя и не короткий ID**.
Если приложение показывает только короткий ID, получите полный ключ из сведений
или экспорта контакта; название пункта зависит от приложения.
**В oMmesh:** профиль контакта ноды рядом с телефоном → «Ещё» →
«Копировать открытый ключ». Это копирует полный ключ.

В **локальной консоли удалённой ноды** отправьте две команды по очереди.
Замените `FULL_PUBLIC_KEY` своим скопированным ключом:

```text
set remote.cli FULL_PUBLIC_KEY on
get remote.cli FULL_PUBLIC_KEY
```

Ожидаемые ответы: сначала `OK`, затем `> on`. После этого продолжайте с шага 3.
Для отзыва права используйте `set remote.cli FULL_PUBLIC_KEY off`.
Нужна консоль приложения с прямой отправкой локальных команд либо сервисная
USB-консоль; поле команд Helper 2.9 эти команды не отправляет.

### Если не получилось

| Что видите | Что проверить |
| --- | --- |
| `Error: denied` | На удалённой ноде включён Remote CLI именно для контакта ноды рядом с телефоном |
| `Error: contact not found` при выдаче доступа | Нода рядом с телефоном добавлена в контакты удалённой; скопирован её полный публичный ключ |
| Тайм-аут | Ноды на связи, выбрана удалённая консоль, на удалённой стоит 0.22. Изменение могло выполниться без ответа: сначала прочитайте значение, не повторяйте запись автоматически |
| `Error: local only` | Эту настройку меняют при непосредственном подключении к ноде; по радио она запрещена |

**USB Helper остаётся 2.9** и управляет нодой на кабеле. Удалённой консоли в нём
нет. База прошивки — **MeshCore 1.18.0**; исправления хранения и запуска nRF52
из 0.21 сохранены. Выпуски 0.20 и 0.21 остаются доступными.

## Что можно делать

- Читать состояние и доступные параметры ноды.
- Управлять звуком, тишиной, индикацией, экраном и другими поддерживаемыми
  настройками. Набор зависит от платы и подключённого оборудования.
- Перезапускать ноду командой `reboot`, включая ошибку сохранения контактов.

Настройка способа локального подключения, подготовка Wi-Fi, выдача прав
другим контактам и сервис ADC остаются локальными. Запись ADC требует USB.
Remote CLI не добавляет плате отсутствующие GPS, экран, усилитель или зуммер.
Команды работают на всех восьми профилях выпуска, включая ProMicro/FakeTec
без дисплея; аппаратные ограничения указаны в [матрице CLI](docs/CLI_BOARD_MATRIX_RU.md).

Remote CLI позволяет читать и чувствительные настройки, включая BLE PIN:
выдавайте право только доверенным контактам. Изменение радиопараметров может
сразу прервать связь с нодой.

## Что важно при работе по радио

**Отправлено — ещё не выполнено.** Сообщение приложения об отправке может
означать только постановку пакета в очередь. Дождитесь ответа ноды, а после
изменения прочитайте значение обратно. При тайм-ауте результат неизвестен:
команда могла выполниться, а ответ — потеряться. Автоматически повторять
изменения нельзя.

**`reboot` — принудительный перезапуск без сохранения.** Несохранённые изменения
в RAM могут потеряться. Сохранённые файлы не форматируются и настройки
не сбрасываются. Нода может перезапуститься раньше отправки ответа; тайм-аут
после этой команды ожидаем. После её возвращения в сеть проверьте состояние.
Полностью зависший процессор, который не обрабатывает команды, таким способом
не перезапустить.

Используется штатное шифрование и проверка сообщений MeshCore; криптографический
протокол не заменён. Защита от повторов по timestamp действует в RAM в пределах
текущего запуска. После перезагрузки старая команда может быть принята повторно:
гарантии «строго один раз» и постоянного журнала команд нет.

Приём и выполнение требуют 0.22 **на удалённой ноде**. SmartUI 0.21 и старее
такой приём не поддерживают. Отправитель может использовать существующую
отправку MeshCore type 3, если она доступна в его прошивке и приложении.
Это не отправка обычного сообщения в чат и не локальная консоль своей ноды.

| Heltec V3 | `Heltec_V3_UI_0.22-update.bin` |
| Heltec V4.3 OLED FEM ON | `Heltec_V4.3_UI_0.22-update.bin` |
| Heltec V4 R8 OLED FEM ON | `Heltec_V4_R8_UI_0.22-update.bin` |
| Wireless Paper FULL | `Paper_UI_0.22-update.bin` |

На nRF52 скопируйте UF2 своей платы в загрузчик **без `FLASH_ERASE`**.
Для работающей совместимой ESP32 установите `update.bin` по `0x10000` без
Erase. `merged.bin` по `0x0` предназначен для чистой установки и удаляет
прежние данные даже без отдельной очистки.

Пределы контактов прежние: **200 для nRF52, 350 для ESP32**.
Если при обновлении nRF52 список больше 200, останутся первые 200 записей
в порядке файла ноды; остальные будут удалены. Заранее сохраните нужные
контакты и идентичность; при необходимости сократите список самостоятельно.
Прежние BLE PIN и выбранный транспорт при обычном обновлении сохраняются.

Восемь профилей, двенадцать образов прошивок, двадцать файлов вложений.
`RELEASE-MANIFEST.json` связывает комплект с одним исходным commit.
Контрольные суммы: `SHA256SUMS.txt` для UF2, `SHA256SUMS-ESP32.txt` для BIN.

## Проверки и ограничения

Публикация требует проверок разрешений контактов, разбора команд и ответов,
защиты локальных операций, повторных и повреждённых запросов, а также сборок
всех восьми профилей. Сохраняются проверки хранения, CLI и локального Helper.
Компьютерные проверки не заменяют испытания радиообмена на физических платах.
Устранение всех причин зависания, остановки TX или повторяющегося `Loading…`
не заявляется.
