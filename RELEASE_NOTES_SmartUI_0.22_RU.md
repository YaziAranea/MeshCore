# Smart UI 0.22 — управление своей нодой через LoRa

**Теперь можно управлять удалённой companion-нодой без подхода к ней.**
Через консоль контакта в совместимом приложении можно прочитать состояние,
изменить доступные настройки и отправить `reboot`. Принимающая нода должна
работать на **SmartUI 0.22** и разрешать управление этому контакту.

База — **MeshCore 1.18.0**. Исправления хранения и запуска nRF52 из 0.21
сохранены. Это отдельный выпуск: 0.20 и 0.21 остаются доступными.
**USB Helper остаётся 2.9**: он настраивает ноду по кабелю, удалённая
LoRa-консоль и новые кнопки управления другой нодой в него не добавлены.

## Как подключить удалённое управление

Пример: нода **А** рядом с телефоном, нода **Б** стоит в машине.

1. Установите SmartUI 0.22 на ноду **Б**.
2. Подключитесь к **Б** обычным локальным способом. В её списке контактов
   найдите именно **А** и включите у этого контакта разрешение **Remote CLI**
   средствами совместимого приложения. Сохраните изменение.
   Если такого пункта нет, локальная команда
   `set remote.cli FULL_PUBLIC_KEY on` выдаёт то же право существующему контакту;
   укажите полный публичный ключ А — 64 hex-символа. Проверка:
   `get remote.cli FULL_PUBLIC_KEY` → `> on`.
3. Подключите телефон к **А**. Откройте удалённую консоль контакта **Б**
   в приложении, которое умеет отправлять штатные команды MeshCore по LoRa.
4. Отправьте `ver`, затем `get battery`. Дождитесь ответа удалённой ноды.
5. Для изменения, например, отправьте `set mute on`, затем прочитайте
   `get mute`, чтобы проверить результат.

**Разрешение выдаётся на принимающей ноде контакту отправителя.** Разрешение
у контакта Б на ноде А не даёт А право управлять Б. Для управления в обе
стороны настройте каждую ноду отдельно. Новый общий пароль и отдельный вход
не нужны. Название пункта Remote CLI и наличие консоли зависят от приложения.

Настройки доступа проверяются по полной идентичности контакта, а не по имени.
Разрешение получать телеметрию и её режим `ALLOW_ALL` права управления не дают.
Неизвестный контакт или контакт без Remote CLI команды не выполняет.

## Что можно делать

- Читать состояние и доступные параметры ноды.
- Управлять звуком, тишиной, индикацией, экраном и другими поддерживаемыми
  настройками. Набор зависит от платы и подключённого оборудования.
- Перезапускать ноду командой `reboot`, включая ошибку сохранения контактов.

Настройка способа локального подключения, подготовка Wi-Fi, выдача прав
другим контактам и сервис ADC остаются локальными. Запись ADC требует USB.
Remote CLI не добавляет плате отсутствующие GPS, экран, усилитель или зуммер.
Команды работают на всех восьми профилях выпуска, включая ProMicro/FakeTec
без дисплея; аппаратные ограничения указаны в [матрице CLI](docs/CLI_BOARD_MATRIX_RU.md).

Remote CLI позволяет читать и чувствительные настройки, включая BLE PIN:
выдавайте право только доверенным контактам. Изменение радиопараметров может
сразу прервать связь с нодой.

## Что важно при работе по радио

**Отправлено — ещё не выполнено.** Сообщение приложения об отправке может
означать только постановку пакета в очередь. Дождитесь ответа ноды, а после
изменения прочитайте значение обратно. При тайм-ауте результат неизвестен:
команда могла выполниться, а ответ — потеряться. Автоматически повторять
изменения нельзя.

**`reboot` — принудительный перезапуск без сохранения.** Несохранённые изменения
в RAM могут потеряться. Сохранённые файлы не форматируются и настройки
не сбрасываются. Нода может перезапуститься раньше отправки ответа; тайм-аут
после этой команды ожидаем. После её возвращения в сеть проверьте состояние.
Полностью зависший процессор, который не обрабатывает команды, таким способом
не перезапустить.

Используется штатное шифрование и проверка сообщений MeshCore; криптографический
протокол не заменён. Защита от повторов по timestamp действует в RAM в пределах
текущего запуска. После перезагрузки старая команда может быть принята повторно:
гарантии «строго один раз» и постоянного журнала команд нет.

Приём и выполнение требуют 0.22 **на удалённой ноде**. SmartUI 0.21 и старее
такой приём не поддерживают. Отправитель может использовать существующую
отправку MeshCore type 3, если она доступна в его прошивке и приложении.
Это не отправка обычного сообщения в чат и не локальная консоль своей ноды.

## Обновление и файлы

| Плата | Файл обычного обновления |
|---|---|
| Heltec T096 FEM ON | `T096_UI_0.22.uf2` |
| Heltec T114 | `T114_UI_0.22.uf2` |
| ProMicro nRF52840 + RA62 с OLED | `ProMicro_RA62_UI_0.22.uf2` |
| ProMicro / FakeTec V4 + HT-RA62 без дисплея | `ProMicro_FakeTec_RA62_Headless_UI_0.22.uf2` |
| Heltec V3 | `Heltec_V3_UI_0.22-update.bin` |
| Heltec V4.3 OLED FEM ON | `Heltec_V4.3_UI_0.22-update.bin` |
| Heltec V4 R8 OLED FEM ON | `Heltec_V4_R8_UI_0.22-update.bin` |
| Wireless Paper FULL | `Paper_UI_0.22-update.bin` |

На nRF52 скопируйте UF2 своей платы в загрузчик **без `FLASH_ERASE`**.
Для работающей совместимой ESP32 установите `update.bin` по `0x10000` без
Erase. `merged.bin` по `0x0` предназначен для чистой установки и удаляет
прежние данные даже без отдельной очистки.

Пределы контактов прежние: **200 для nRF52, 350 для ESP32**.
Если при обновлении nRF52 список больше 200, останутся первые 200 записей
в порядке файла ноды; остальные будут удалены. Заранее сохраните нужные
контакты и идентичность; при необходимости сократите список самостоятельно.
Прежние BLE PIN и выбранный транспорт при обычном обновлении сохраняются.

Восемь профилей, двенадцать образов прошивок, двадцать файлов вложений.
`RELEASE-MANIFEST.json` связывает комплект с одним исходным commit.
Контрольные суммы: `SHA256SUMS.txt` для UF2, `SHA256SUMS-ESP32.txt` для BIN.

## Проверки и ограничения

Публикация требует проверок разрешений контактов, разбора команд и ответов,
защиты локальных операций, повторных и повреждённых запросов, а также сборок
всех восьми профилей. Сохраняются проверки хранения, CLI и локального Helper.
Компьютерные проверки не заменяют испытания радиообмена на физических платах.
Устранение всех причин зависания, остановки TX или повторяющегося `Loading…`
не заявляется.
