## Что исправлено относительно SmartUI V4

Пункт `Система → LED платы` теперь является общим выключателем встроенных
светодиодов, которыми управляет прошивка:

- при `LED платы: ВЫКЛ` штатный status LED остаётся выключенным;
- LoRa TX больше не может снова зажечь встроенный TX LED;
- GPIO уведомления, совпадающий со встроенным LED платы, также подчиняется
  общему выключателю;
- если внешний LED подключён к отдельному GPIO, он остаётся независимым
  и управляется своими настройками уведомлений;
- выключение применяется сразу и передаётся штатному механизму сохранения настроек.

На ProMicro автономный connection LED отключается до `Bluefruit.begin()`;
работа BLE не отключается. При операциях nRF52 framework с flash/cache возможен
редкий короткий импульс встроенного LED. Это не периодическое BLE-мигание,
не LoRa TX и не признак непрочитанного ЛС. Абсолютное отсутствие любого
электрического импульса на каждом экземпляре не обещается.

**LoRa TX и непрочитанное сообщение — разные события.** Передача радио может
происходить без нового ЛС; V5 не блокирует передачу, а только вспышку встроенного
индикатора. Отдельный физический LED зарядки может продолжать гореть, если он
подключён напрямую к контроллеру питания и не управляется MCU. Прошивка не может
гарантировать отключение такого индикатора.

## Что сохранено из V4

- Напоминание о непрочитанном важном ЛС/упоминании на nRF52840 планируется
  через 120 секунд от начала предыдущей серии.
- Серия на T096/T114/ProMicro содержит ровно два проигрывания выбранной мелодии;
  повторный callback не перезапускает активную серию.
- Тихий режим блокирует звук. Настройки мелодии, GPIO, режима уведомлений,
  калибровки, контактов и identity не сбрасываются.
- Для звука важного события пользователь по-прежнему выбирает «Зумер» или «Оба»;
  режимы «Свет» и «Выкл» звука не дают.
- Mute-иконка без текста «ТИХО», структура меню, клавиатура, адресная отправка,
  шрифты, темы, BLE PIN и синхронизация времени не менялись.
- В `Система → Управление` добавлены две короткие подсказки:
  `LED: радио и ЛС` и `ВЫКЛ: LED погаснут`. Скриншоты настроек обновлены.
- Радиопараметры, FEM/LNA и энергосбережение не менялись.

Заставка показывает `MeshCore` и короткое `V5`; уникальный board marker остаётся
внутри прошивки для проверки правильного файла.

## Какой файл скачать

`V5` — номер SmartUI, не модель платы.

| Плата | Файл |
|---|---|
| T096 FEM ON | `T096_UI_V5.uf2` |
| T114 с TFT | `T114_UI_V5.uf2` |
| ProMicro nRF52840 + RA62 | `ProMicro_RA62_UI_V5.uf2` |

UF2 копируется на загрузочный USB-диск соответствующей nRF52840-платы.

| ESP32-S3 | Чистая установка | Обновление работающей ноды |
|---|---|---|
| Heltec V3 OLED | `Heltec_V3_UI_V5-merged.bin` | `Heltec_V3_UI_V5-update.bin` |
| Heltec V4.3 OLED FEM ON | `Heltec_V4.3_UI_V5-merged.bin` | `Heltec_V4.3_UI_V5-update.bin` |
| Wireless Paper FULL | `Paper_UI_V5-merged.bin` | `Paper_UI_V5-update.bin` |

- **Обычное обновление ESP32: `-update.bin`, адрес `0x10000`, без Erase.**
- **Чистая установка: `-merged.bin`, адрес `0x0`.** Это не обновление.
  Имя для web flasher должно заканчиваться точно на `-merged.bin`.

Сохраните ключ ноды, контакты и настройки до эксперимента. Не публикуйте
резервную копию. Erase Flash и V3 merged могут удалить данные.

### Heltec V3: merged стирает данные даже без Erase

`Heltec_V3_UI_V5-merged.bin` содержит подготовленную пустую SPIFFS и
перезаписывает identity, контакты и настройки **даже без Erase Flash**.
Для сохранения работающей ноды используйте update без очистки.

FS2 по-прежнему разрешает автоматическую подготовку только при точном SHA256
известного пустого образа и правильной разметке. Произвольное повреждение,
FF-раздел и ошибка чтения не разрешают молчаливое форматирование; другой сброс
требует двух подтверждений. Это не новая аппаратная проверка V5.

### V4.3/Paper: ограничение чистой установки не исправлено

Механизм хранилища не менялся. Их merged **не содержит подготовленной SPIFFS**:
после полной очистки возможен `STORAGE ERROR`. Работающую ноду обновляйте
update без Erase. BIN другой платы не подходит.

## Проверки и границы

Публикация разрешена только после зелёного CI: шесть целевых сборок,
три UF2, три пары BIN, V3 FS2, native-тесты, UI и release-валидаторы.
В V5 добавлены:

- `test_board_led_control_v5.py` — hardware gate встроенного LED, включая TX;
- `test_board_led_ui_v5.py` — UI, немедленное применение и неизменность выбранных
  параметров уведомлений в in-memory preferences.

Сохранены проверки напоминаний, двух проигрываний, mute и GPIO из V4.
Это программные проверки. UI harness не является проверкой записи/чтения реальной
flash после цикла питания. Проверки не доказывают полярность, яркость и электрическую
распайку каждого экземпляра, не управляют аппаратным LED зарядки.

Выпуск содержит **14 assets**: девять прошивок, два файла SHA256,
`RELEASE-MANIFEST.json`, эти примечания и `SmartUI_V5_all-boards.zip`.
Манифест связывает всё с одним исходным commit. Повтор публикации обновляет
страницу тега `smartui-v5`, не создаёт дублирующий Release.
