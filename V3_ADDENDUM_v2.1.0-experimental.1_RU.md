# Heltec V3 OLED — SmartUI 2.1.0-experimental.1, исправление FS2

> [!WARNING]
> Это дополнение к экспериментальному UI, не объявленная стабильная прошивка.
> V3 добавлен на ту же страницу Release. Пять ранее опубликованных прошивок,
> их архив и исходный тег не заменяются. beta.2 остаётся Latest.
>
> **V3 merged FS2 — только для чистой установки:** он записывает пустое
> хранилище и удаляет сохранённые identity/настройки **даже без Erase Flash**.
> Для работающей ноды используйте **update BIN без очистки**.

## Что исправляет FS2

После полной очистки flash прежняя V3-сборка могла показывать `STORAGE ERROR`:
пустой раздел SPIFFS не содержал файловой системы, а запуск с `SPIFFS.begin(false)`
не форматирует его автоматически. Повторная очистка это не исправляла.

**FS1 не устранила ошибку на пользовательской V3**, хотя образ успешно прошёл
host-проверки. Конкретная причина отказа на плате пока не установлена.

FS2 сохраняет пустое SPIFFS в merged и добавляет восстановление штатной библиотекой
платы. При ошибке mount автоматическая подготовка разрешена только для раздела
с точными адресом/размером и SHA256 известного пустого заводского образа.
Любые другие данные, стертый FF-раздел и ошибки чтения не разрешают этот путь.

Если это не помогло, экран предлагает восстановление с **двумя отдельными
подтверждениями кнопкой**. Оно удаляет identity, контакты и настройки; отказ или
бездействие не стирают данные. Между подтверждениями нужно отпустить кнопку.
Обычный **update.bin** записывает только приложение; само восстановление во время
запуска подчиняется тем же ограничениям. Успешная аппаратная проверка FS2 пока
не заявляется — это не обещание гарантированного устранения ошибки.

Управление экраном восстановления: один щелчок **PRG/BOOT** выбирает следующий
пункт, удержание 2 секунды с последующим отпусканием выполняет его. Для сброса:
`Сброс данных` → удержать/отпустить → выбрать `Стереть` → снова удержать/отпустить.
Первоначально в подтверждении выбрана `Отмена`. `Выключить` доступно без запуска
обычного UI и не меняет сохранённые данные. В заголовке ошибки есть `FS2` и код
ESP32; если восстановление не удалось, приложите фотографию этого экрана.

**Особенность meshcore.io/flasher:** у custom BIN адрес определяется по имени.
Имя merged должно оканчиваться строго на `-merged.bin`, без ` (1)` перед `.bin`.
Обновите страницу перед выбором файла. Для merged должно появиться предупреждение
о полной установке; это известная ловушка имени, но не доказанная причина отказа FS1.

Имена файлов остались прежними, но V3-файлы и общий архив обновлены на той же
странице Release. **Скачайте их заново**, вместе с актуальными контрольными
суммами. В V3-манифесте указана ревизия `FS2`; маркер приложения —
`V3 OLED SmartUI 2.1.0-experimental.1 FS2`.

- [Чистая установка со сбросом данных — merged BIN FS2](https://github.com/YaziAranea/MeshCore/releases/download/v2.1.0-experimental.1/Heltec_V3_OLED_SmartUI_2.1.0-experimental.1-freshInstall-merged.bin), адрес `0x0`, для совместимого web flasher.
- [Новый общий архив для шести плат](https://github.com/YaziAranea/MeshCore/releases/download/v2.1.0-experimental.1/MeshCore_SmartUI_2.1.0-experimental.1_all-six-boards.zip).

Прошивка предназначена именно для **Heltec WiFi LoRa 32 V3 с OLED 128×64**.
Не для V2, V4 или Wireless Stick. Это ESP32-S3: UF2 для неё не подходит.
Перед экспериментом сохраните identity и нужные данные приватным безопасным
способом. Не публикуйте приватный ключ или резервные настройки.

## Какой вариант нужен вам

| Состояние V3 | Файл и способ |
|---|---|
| Нода работает, нужно сохранить её данные | `update.bin`, адрес `0x10000`, **без Erase Flash** |
| Flash уже очищена; после Erase появился `STORAGE ERROR` | Свежескачанный **merged FS2**, адрес `0x0`; повторять Erase не требуется |
| Нужна осознанная полная переустановка | **merged FS2**, адрес `0x0`; identity/настройки будут удалены независимо от галочки Erase |

**Update при прошивке не записывает файловую систему.** FS2 может предложить её
создание только через описанный безопасный сценарий восстановления. При `STORAGE ERROR`
на ранее работающей ноде без очистки не применяйте merged как безусловное
«лечение»: сначала сохраните доступные данные и выясните причину.

## Что доступно

Часы с аптаймом под ними, пять OLED-стилей, компактное меню и избранное,
клавиатура с Ё, адресная отправка с подтверждением, недавние получатели,
отбор по первой букве, непрочитанные ЛС, новые пиктограммы, калибровка ADC
и ручная страница постоянного BLE PIN.

У штатной V3 нет GPS, внешнего FEM и встроенного зуммера: соответствующие
несуществующие функции не изображаются на экране, GPIO для зуммера не назначается.
Защита АКБ по умолчанию — 3,2 В, при её отключении остаётся нижний порог 2,7 В.
Радиодрайвер, параметры платы и power saving взяты из существующей V3-конфигурации.

Управление — кнопкой **PRG/BOOT (GPIO0), не RST**. Один щелчок — вперёд,
двойной — назад, удержание — выбор; первое нажатие при выключенном экране
может только разбудить его. В первые восемь секунд удержание вызывает CLI Rescue.

## Исходники и происхождение файлов

V3 собран из дополненного коммита ветки
[`smartui-2.1-experimental.1`](https://github.com/YaziAranea/MeshCore/tree/smartui-2.1-experimental.1).
Точный SHA находится в `RELEASE-MANIFEST-V3.json`; его можно использовать
с `git checkout <SHA>` для воспроизводимой сборки.

```text
pio run -e Heltec_v3_companion_radio_ble_smartui -t mergebin
```

Автоматические ссылки GitHub **Source code** у исходного тега относятся к первым
пяти платам. Для исходников с профилем V3 используйте указанную ветку или точный
коммит из V3-манифеста. Исходный тег намеренно не передвигается.

Старый `all-five-boards.zip` остаётся прежним и V3 не содержит. Новый
`all-six-boards.zip` объединяет прежние пять прошивок без пересборки и дополнение
V3; манифест внутри отдельно указывает происхождение каждой прошивки.
Контрольные суммы отдельных V3 BIN находятся в `SHA256SUMS-V3.txt`.

## Проверки и ограничения

Проверяются сборка V3, структура ESP32-S3 образов, совпадение application slice
merged-файла с update BIN, маркер FS2, подготовленное пустое SPIFFS и SHA-256. OLED-модель использует
встроенные glyph-таблицы всех пяти стилей и геометрию 128×64: часы, меню,
клавиатура, адресаты и подтверждение отправки.

[Галерея V3 и остальных плат](https://github.com/YaziAranea/MeshCore/blob/smartui-2.1-experimental.1/docs/SCREENS_RU.md).

Это программная проверка и симуляция, **не испытание на физической V3**.
На плате нужно проверить пробуждение кнопкой, напряжение/калибровку, BLE,
читаемость дисплея и отправку сообщения.

**Известное ограничение V4.3 и Wireless Paper:** их ранее опубликованные файлы
в этом исправлении не пересобираются. После Erase пустое SPIFFS на этих целях
также может вызвать `STORAGE ERROR`; FS2 относится только к V3. Работающие
ноды обновляйте совместимым update без очистки. **V3 BIN на них не устанавливайте.**
