# SmartUI 0.13: локальные команды настройки

SmartUI 0.13 использует локальные companion-команды MeshCore: CMD66 и RESP29.
Это backport локального интерфейса; версия основного companion-протокола остаётся 13.
Это не новый протокол радио и не удалённое управление чужой нодой через LoRa.

1. Для обычной настройки есть USB Helper 1.6. В режиме «Настройки (USB-компаньон)»
   он работает через один USB-порт и не забирает сообщения.
2. Для приложения используйте уже выбранное локальное подключение BLE, USB или
   Wi-Fi/TCP и его общую очередь команд. Не открывайте второй читатель транспорта.
3. Поддержка определяется через discovery и hello, а не по номеру прошивки.
4. API 0.11 с opcode 201, sync, событиями и отметками прочтения в 0.13 **не поддерживается**.
   Его описание и Helper 1.4 остаются в [архиве 0.11](https://github.com/YaziAranea/MeshCore/tree/smartui-0.11/tools/smartui-api).
   Обычные команды сообщений MeshCore сохраняются; локальный CLI не заменяет их.

[SDK и примеры](../tools/smartui-cli/README.md) включают Python-клиент и общую
JavaScript-реализацию из Helper. Автоматические проверки используют симуляцию;
испытания конкретных плат, USB и BLE не заявляются.

## Обнаружение и транспорт

После штатного handshake запросите custom variables: CMD40, ответ RESP21.
В CSV должна быть ровно одна запись `smartui_cli:1`. Отсутствие или другая версия —
неподдерживаемый интерфейс. Маркер `smartui_api:1` не подходит. Затем:

`ui hello`

Ответ:

`OK ui hello version=1 firmware=0.13 max_command=156 max_reply=156 write=1 sync=0 events=0 meshcore=1`

`meshcore=1` означает, что на том же CMD66 работают и команды оригинального
MeshCore (раздел «Команды оригинального MeshCore» ниже).

`write=0` разрешает чтение, но не обход защиты хранилища. Не включайте кнопки
несуществующего оборудования по одному названию платы: читайте `ui caps KEY`.
Возможность сборки не доказывает физическое наличие зуммера, GPS или дисплея.

Полезная нагрузка запроса — байт 66 и команда в UTF-8 без управляющих символов.
Ответ — байт 29 и текст.
Helper и SDK добавляют префикс из двух латинских букв/цифр и `|`:

`[66] + "a9|ui get volume"` → `[29] + "a9|OK ui get key=volume value=7"`

Весь кадр — не более 160 байт. С префиксом остаётся 156 байт команды/ответа.
Нет NUL, перевода строки, разбиения ответа на страницы или multipart. Для USB/TCP
снаружи используется штатное обрамление: `<`, uint16 little-endian длина, запрос;
ответ — `>`, uint16 little-endian длина, полезная нагрузка. BLE передаёт целый
companion-кадр в штатной характеристике: не добавляйте USB-заголовок и не делите
команду на произвольные записи. Для максимального 160-байтового кадра требуется
подходящий фактически согласованный ATT MTU, обычно не менее 163 байт.

Команды `ui` и их ответы — ASCII; названия мелодий передаются UTF-8 hex.
Команды оригинального MeshCore принимают UTF-8 там, где это текст (`set name Дача`);
их ответы допускают корректный UTF-8, включая русское имя ноды.

## Команды оригинального MeshCore

Те же имена и ответы, что у companion CLI оригинального MeshCore (ветка dev,
upstream PR #3298 и следующие): `OK`, `> значение`, `Error, …`. Приложение,
написанное для оригинала, работает с SmartUI без отдельной ветки кода.
Изменения проходят те же проверки и сохранение с откатом, что и двоичные команды
с тем же действием, и те же запреты `readonly` и `busy`, что и `ui set`.

| Команда | Ответ и смысл |
| --- | --- |
| `board`, `ver`, `get name`, `get radio`, `get freq` | Чтение |
| `set name ИМЯ` | До 31 байта UTF-8, без `[ ] \ : , ? *`; иначе `Error, bad chars` |
| `set pin N` | `0` или шесть цифр; ответ `> pin is now N` |
| `get/set tx` | От −9 до предела платы, дБм |
| `get/set af`, `get/set dutycycle`, `get/set rxdelay` | Как в оригинале; одна запись настроек задержек |
| `get/set multi.acks`, `get/set path.hash.mode` | 0–255 и 0–2 |
| `get/set radio.rxgain on\|off` | Не во время приёма или передачи: иначе `Error: busy` |
| `get/set tz.offset` | Часы от −12 до +14, допускается половина часа (`5.5`) |
| `set radio F,BW,SF,CR` | МГц и кГц, как в оригинале. Применяется сразу через ту же транзакцию, что `ui radio set`, с текущим `path_bytes`; оригинал отвечает `OK - reboot to apply`, SmartUI — `OK` |
| `reboot`, `poweroff`, `shutdown` | Ответа нет, как в оригинале. `Error: storage`, если не удалось сохранить отложенные контакты |
| `get wifi.status`, `get wifi.ip` | Чтение |

Чего в SmartUI нет или что сделано иначе:

1. `cad`, `int.thresh`, `agc.reset.interval`, `txdelay`, `direct.txdelay` —
   `Error: unsupported`. AGC в SmartUI — переключатель `ui set agc_reset`, не интервал.
2. `get wifi.pwd` — `Error: password is not readable`. Остальные `wifi.*` —
   `Error: use ui wifi`: сеть меняется только через проверку и сохранение.
3. Удалённое выполнение команд по LoRa не добавлено.
4. Команда, которой нет ни в одном варианте, отвечает `Unknown command`.

## Очередь, ошибки и повторное подключение

1. Один запрос в работе. Сначала сопоставьте RESP29 и точный префикс, затем
   завершайте соответствующий запрос общей очереди приложения.
2. Штатные push-пакеты и чужой префикс не завершают запрос CLI. В 0.13 нет
   CLI-push, событий API, автоопроса inbox и подтверждения прочтения.
3. Известный отказ `ERR ui REASON`, `Unknown command` или `Error: ...` завершает
   команду без повторной отправки. Не показывайте и не записывайте сырой текст
   ошибки: он может содержать сведения, которые приложение не планировало раскрывать.
4. Пустой CMD66 или кадр больше 160 байт отклоняется штатным бинарным `[1,6]`.
   Валидный префикс отражается в обычном RESP29, включая ошибки и неизвестные команды.
   Клиент отправляет только корректные префиксы и печатный ASCII.
5. Тайм-аут, разрыв транспорта или повреждённый ответ не доказывают откат записи.
   Заблокируйте новые команды этой сессии, переподключитесь и прочитайте состояние.
   Автоматически повторять изменение нельзя.
6. Теги не переиспользуются в одной сессии. В поставляемых клиентах после
   3844 запросов требуется новое подключение; переполнение не оборачивается в ноль.

Основные причины `ERR ui`: `invalid`, `unsupported`, `readonly`, `busy`,
`storage`, `stale`, `source`, `measurement`, `range`, `transport`,
`unconfigured`, `notready`, `unavailable`, `buffer`, `internal`.
Неизвестный ключ caps/get — `invalid`; известный отсутствующий у backend — `unsupported`.
Ошибка `storage` требует диагностики и чтения состояния, не Erase и не обхода readonly.

## Ключи и команды

`ui caps KEY` → `OK ui caps key=KEY value=NUMBER`.

Ключи возможностей:

`v adc sound board_led unread_led vibration gps battery_protection display melody_max adc_min adc_max agc_reset fem_lna fem_pa bridge melody_names`

`ui get KEY` → `OK ui get key=KEY value=NUMBER`.

Ключи текущего состояния:

`battery_mv adc_multiplier adc_default sound_quiet volume melody board_led unread_led vibration gps battery_protection shutdown_mv muted agc_reset fem_lna fem_pa bridge`

`ui set KEY UINT` → `OK ui set key=KEY value=UINT`.

Изменяемые ключи:

`sound_quiet volume melody board_led unread_led vibration gps battery_protection muted agc_reset fem_lna fem_pa bridge`

Булевы значения — 0/1. Громкость — 1–10, мелодия — 0…`melody_max`.
Неподдерживаемые функции скрывайте или отключайте. После успешного set перечитайте
именно сохранённый параметр; не заменяйте подтверждение локальным значением поля.

| Команда | Результат и смысл |
| --- | --- |
| `ui melody ID` | `OK ui melody id=N name_hex=HEX`; UTF-8 название, если `melody_names=1` |
| `ui test` | `OK ui test`; обычное уведомление с сохранёнными каналами и общей тишиной |
| `ui adc preview MV` | `OK ui adc_preview token=N sampled_mv=N measured_mv=N multiplier=FLOAT`; ничего не сохраняет |
| `ui adc apply TOKEN` | `OK ui adc_apply`; отдельное подтверждённое сохранение |
| `ui adc reset` | `OK ui adc_reset`; только заводской множитель ADC |
| `ui connection` | `OK ui connection mode=ble\|usb\|wifi client=none\|ble\|usb\|wifi caps=N write=0\|1` |
| `ui mode ble\|usb\|wifi` | `OK ui mode target=MODE state=active\|pending`; применение после ответа и освобождения TX |
| `ui mode status` | `OK ui mode pending=none\|ble\|usb\|wifi error=none\|cancelled\|timeout\|readonly\|apply\|storage` |

Ответ на `ui test` означает приём команды, а не физически проверенный звук.
`muted=1` подавляет уведомления; обычные LED состояния могут остаться включёнными.
`bridge=1` — двухвыводный мостовой привод совместимого плавающего пьезоизлучателя,
не передача аудиопотока. Такой выход нельзя соединять с землёй. API не играет
подтверждающий тон при переключении bridge.

AGC по умолчанию выключен. Включение разрешает пробную профилактику через 60 секунд
с отсрочкой при активности радио. Это не перезагрузка ноды, не гарантированное
исправление приёма; во время процедуры есть короткое окно без RX.

ADC: MV — 2500…4500 мВ, множитель ограничен `adc_min`/`adc_max`. Токен действует
до 60 секунд; изменение исходной калибровки делает его непригодным. На ProMicro
нужен свежий замер от АКБ не старше 120 секунд с тем же множителем: запустите
ноду от АКБ, дождитесь замера, подключите USB без перезапуска и сделайте preview
в течение двух минут. `source` означает отсутствие пригодного опорного замера.
USB-показание не следует считать напряжением аккумулятора. Проверяйте мультиметром
непосредственно на АКБ. Factory ADC reset не удаляет контакты и ключ ноды.

## Радио и автоанонс — добавлено в 0.13

Новые возможности проверяйте отдельными чтениями `ui radio` и `ui advert`.
`smartui_cli:1` существовал и в 0.12: сам маркер не гарантирует новые команды.
Неизвестная команда на прежней прошивке отключает только соответствующую функцию
клиента, а не остальные настройки. При повреждённом ответе или тайм-ауте действует
общее правило прекращения сеанса и повторного чтения после подключения.

```text
ui radio
OK ui radio freq_khz=868731 bw_hz=62500 sf=7 cr=7 path_bytes=2 tx_dbm=20 repeat=0

ui radio set 868731 62500 7 7 2

ui advert
OK ui advert interval_min=60

ui advert set 120
```

Радиочисла выше — пример формата, не универсальный пресет. Аргументы строго
целые: частота в **кГц**, полоса в **Гц**, SF, знаменатель CR (7 означает 4/7),
длина хэша пути в байтах. Пять полей применяются одной транзакцией. Мощность
передачи, FEM и включение ретрансляции команда не меняет. Если существующая
ретрансляция несовместима с новой частотой, возвращается `ERR ui repeat` без
молчаливого выключения ретрансляции.

Поддерживаемые пределы дополнительно проверяет драйвер конкретного радио.
Проверка программного диапазона не определяет разрешённость частоты или полосу
физического RF-тракта платы. Клиент должен показывать параметры до применения.
Helper при выборе города сохраняет текущий `path_bytes`: источник пресетов
не предоставляет достоверное значение этого поля.

При отказе настройки или сохранения восстанавливаются прежние значения.
`restore` означает, что восстановить рабочую конфигурацию радио не удалось;
нельзя показывать старые параметры как подтверждённо работающие. Чтение после
успешного изменения подтверждает состояние прошивки, а не приём пакетов в эфире.
Тайм-аут не разрешает повторять `set`: переподключитесь и перечитайте состояние.

Автоанонс использует то же поле настроек и тот же таймер, что экранное меню:
`0` (выключен), `15`, `30`, `60`, `120`, `180` минут. Повторное сохранение того
же интервала не отодвигает следующий анонс. Это интервал, не время суток.
Сохранение другого интервала пересчитывает таймер; мгновенный анонс не отправляет.
Тип анонса не меняется: существующий локальный zero-hop, не новый flood-режим.

Сервисная USB-консоль при выбранном на ноде BLE/Wi-Fi использует те же операции
с префиксом `settings`: `settings radio`, `settings radio set ...`,
`settings advert`, `settings advert set N`. Ответы начинаются `OK settings`
или `ERR settings`. Это текстовый сервисный порт, не companion-обрамление.

## Wi-Fi: только через BLE или USB

Смена сети требует непрерывного подключения через BLE или USB. Не настраивайте
сеть через тот TCP-канал, который меняете. Обычные настройки через TCP доступны
в рамках существующей доверенной локальной сети; отдельной аутентификации и TLS нет.
Не публикуйте порт 5000 в интернете.

Последовательность:

1. `ui wifi begin`.
2. `ui wifi ssid HEX`: 1–32 байта UTF-8, закодированных hex.
3. `ui wifi password HEX` либо `ui wifi password -` для явно выбранной открытой сети.
   Пароль — 8–63 байта либо 64 ASCII hex-символа PSK; аргумент всё равно hex-кодируется.
4. `ui wifi test`.
5. `ui wifi status`, пока проверка не закончится.
6. Только при `state=test_ok` и явном согласии пользователя — `ui wifi save`.
   Иначе `ui wifi cancel`.

Статус: `OK ui wifi state=STATE supported=0|1 configured=0|1 associated=0|1 ip=none|IPv4`.
После сохранения статус `saved`. Успешный тест сам по себе не сохраняет сеть.
При ошибке теста старые реквизиты остаются. Отмена, 120 секунд бездействия или смена
сессии очищают незавершённый черновик. Пароль не читается обратно.
Не логируйте команды, пакеты, hex реквизитов, DeviceInfo с PIN или весь exception.

## Проверка клиентской реализации

Документация описывает протокол и не предполагает интеграцию с каким-либо
конкретным приложением. Выбор архитектуры и пользовательского интерфейса
остаётся за разработчиком клиента.

1. Обнаружение CMD40/RESP21 и `ui hello` предшествует чтению caps/get.
   Форма настроек учитывает объявленные возможности платы.
2. CMD66/RESP29 обслуживаются общей очередью локального companion-подключения,
   не удалёнными командами LoRa. Ответ сопоставляется по точному префиксу.
3. Тесты охватывают чужой RESP29, штатный push между запросом и ответом,
   ошибку и тайм-аут записи, UTF-8 имя, предел 160 байт, readonly и старую прошивку.
4. Логи не содержат реквизиты из CMD66/RESP29 и PIN из DeviceInfo.
   Для BLE проверяется фактически согласованный MTU всего транспортного пути.
5. Получение сообщений остаётся штатным: CLI 0.13 не синхронизирует прочтение
   с нодой. Кодеки и фикстуры Developer Kit служат примерами, не готовым
   адаптером для любого языка или фреймворка.
