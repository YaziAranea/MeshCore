# SmartUI — управление нодой через CLI

**SmartUI 0.17.** Компактный интерфейс обнаруживается по `control=1` в ответе
`ui hello`. Прежняя 0.16 без этого
признака не поддерживает все новые команды.

**Сначала выберите свою плату:** [матрица доступности команд для семи плат](CLI_BOARD_MATRIX_RU.md).
Она отделяет доступность настройки от наличия подключённого модуля и объясняет
случаи, когда `get` возвращает число, но изменение не поддерживается.

Команды вводятся в **локальной консоли своей ноды** в приложении. Приложение
передаёт их через MeshCore CMD66/RESP29 по Bluetooth, USB-компаньону или Wi-Fi.
Это не команды в LoRa-чат. Обычный USB-терминал использует другой синтаксис,
описанный в конце документа.

## Основная логика

| Действие | Команда | Ответ |
| --- | --- | --- |
| Прочитать | `get volume` | `> 7` |
| Изменить и сохранить | `set volume 8` | `OK` |
| Проверить результат | `get volume` | `> 8` |
| Узнать варианты | `schema volume` | `OK schema key=volume supported=1 min=1 max=10 step=1 options=-` |

Одна команда — один ответ. После `set` отдельная `save` не нужна. Исключения:
ADC через `preview/apply` и Wi-Fi через `test/save`. При отсутствии ответа
переподключитесь и прочитайте состояние: запись могла выполниться, повторять
её автоматически нельзя. `help` локального CLI удалены; инструкция хранится здесь.
Сервисный USB сохраняет старый handshake, используемый Helper.

Переключатели: `on`/`off` или `1`/`0`. Дроби — с точкой. `N`, `TOKEN`, `VALUE`
заменяются вашими значениями. `schema` описывает скалярные настройки SmartUI,
а не любую команду. `supported=0` — функция недоступна; список `options`
имеет приоритет над диапазоном min/max. Успешное чтение старого значения
не доказывает поддержку изменения.

## Звук и уведомления

| Команда | Действие |
| --- | --- |
| `set sound on` / `set sound off` | Разрешить / запретить звук уведомлений |
| `get sound` | 1 — звук разрешён, 0 — запрещён |
| `set mute on` / `set mute off` | Включить / выключить общую тишину уведомлений |
| `get mute` | Состояние общей тишины |
| `set volume 7` | Громкость 1–10; ноль не используется |
| `set melody 18` | Выбрать и сохранить мелодию №18 |
| `get melody` | Номер выбранной мелодии |
| `melody 18` | Узнать название; не выбирать и не играть |
| `melodies` | Выбранный и максимальный номера: `> current=18 max=30` |
| `sound preview` | Один раз прослушать сохранённую мелодию |
| `test` | Проверить обычное уведомление с текущими каналами |
| `set vibration on` / `set vibration off` | Разрешить / запретить вибрацию |
| `set night_quiet on` / `set night_quiet off` | Включить ночную тишину до утра / отменить её |

```text
set melody 18
get melody
sound preview
```

Прослушивание использует сохранённые громкость и вывод, игнорирует каналы и
`sound=off`, но при **`mute=on` не запускается**. Ответ `OK sound_preview`
подтверждает запуск, а не физический звук. `test` учитывает все ограничения:
при канале только LED тишина ожидаема. Мелодия 0 — импульс для активного
зуммера; пассивный пьезо может щёлкать.

`night_quiet`: ночное окно **23:30–07:30 по часам ноды**. Включение требует
достоверного времени; вне окна — `Error: time`. При уже включённой ручной
общей тишине — `Error: muted`: ночной режим не должен снять её утром.
Ночная тишина автоматически снимается утром. Старая сессия, пропустившая утро,
также получит `Error: time` до автоматического сброса. Выключение работает без часов;
если ночной режим не активен, ручной mute остаётся как был.
Явный `set mute on/off` отменяет ночной режим. После изменения любого из этих
двух переключателей приложение перечитывает `get mute` и `get night_quiet`.

Дополнительные параметры: `get KEY` / `set KEY VALUE`.

| KEY | Значения и назначение |
| --- | --- |
| `notify_mode` | Каналы обычных уведомлений: 0 — нет, 1 — LED, 2 — звук, 4 — вибро; складываются |
| `important_notify_mode` | Те же каналы для важных сообщений |
| `melody_system` | Общая мелодия в публичных сборках; основной ключ — `melody` |
| `tone_8bit` | 8-битный стиль, on/off |
| `high_drive` | Усиленный режим выхода, on/off; переключение устанавливает громкость 10 |
| `resonance_hz` | 1800, 2200, 2600, 3000, 3400, 3800, 4200 Гц |
| `sound.bridge` | Мостовое управление совместимым пьезоизлучателем, on/off |

`set notify_mode 3` выбирает LED+звук. Разрешённые комбинации — в schema.
Для сборок с уведомлением только о важных сообщениях также учитывается
`important_notify_mode`. Отдельная запись `melody_dm`/`melody_mention` в текущих
публичных профилях выключена. `tone_8bit`, `high_drive`, `resonance_hz` и мост
предусмотрены для T096/T114; проверяйте поддержку конкретной ноды.
Мост — электрическая схема между двумя выводами. Не соединяйте плавающий
пьезоизлучатель с землёй и не включайте мост для неподходящей нагрузки.

## Выводы, LED, экран

Для каждой строки: `get KEY`, `set KEY VALUE`; ограничения — `schema KEY`.

| KEY | Назначение |
| --- | --- |
| `led_pin` / `tone_pin` / `vibe_pin` | Вывод LED / звука / вибро; `vibe_pin=-1` отключает выход |
| `board_led` | Штатная индикация платы, on/off |
| `unread_led` | Световое напоминание о непрочитанном, on/off |
| `offline_dm_led` / `ble_dm_led` | Световая индикация ЛС без приложения / с приложением, on/off |
| `msg_popup` | Всплывающий экран сообщения, on/off |
| `ui_font` / `ui_theme` | Номер шрифта / темы; варианты зависят от экрана |
| `ui_top_color` / `ui_bottom_color` | Цвет верхней / нижней области, 0–5; в публичных профилях только T096 |
| `backlight_timeout` | Для TFT/OLED: 0 = 15 с, 1 = 30 с, 2 = 60 с; на Paper значение сохраняется, но автоотключение экрана не включает |
| `profile` | 0 = свой, 1 = тихий, 2 = улица, 3 = ночь |

Пины — Arduino-номера из `options` своей платы, не номера разъёма. Перед
переназначением читайте schema заново: доступность зависит от других выходов
и периферии. Не назначайте один вывод нескольким функциям. Мотор нельзя питать
напрямую от GPIO; внешнему LED нужен ограничитель тока.

Профиль меняет группу настроек; после него перечитайте звук, LED, тайм-аут
и тему. Профиль 3 и временный `night_quiet` — разные операции.

## ADC: корректировка напряжения

| Команда | Назначение |
| --- | --- |
| `get battery` | Напряжение, мВ: 4100 = 4,1 В |
| `get adc` | Текущий поправочный коэффициент |
| `get adc.default` | Заводской коэффициент |
| `caps adc_min` / `caps adc_max` | Разрешённые границы коэффициента |
| `set adc VALUE` | Сохранить известный коэффициент, не напряжение в вольтах |
| `adc preview MV` | Рассчитать поправку по мультиметру; ничего не сохранять |
| `adc apply TOKEN` | Подтвердить и сохранить расчёт |
| `adc reset` | Вернуть только заводской коэффициент ADC |

По мультиметру:

1. Измерьте АКБ. При показании **3,32 В** отправьте `adc preview 3320`.
2. Проверьте `sampled_mv`, `measured_mv`, `multiplier` и `token` в ответе.
3. Менее чем через 60 секунд отправьте `adc apply TOKEN`, подставив выданное число.
4. Прочитайте `get adc` и `get battery`.

Измерение — 2500–4500 мВ; коэффициент тоже должен попадать в границы платы.
Прямой ввод: положительное число с точкой, до 6 знаков после неё, без экспоненты.
Ноль не сбрасывает калибровку. Между preview и apply не меняйте коэффициент.
ProMicro нужен замер от АКБ без влияния USB не старше 120 секунд; по Bluetooth
можно работать без USB-питания. `adc manual` проверяет поддержку прямого ввода.

Если неверный ADC не даёт закончить калибровку: `adc service` читает состояние,
`adc service start` включает окно до 120 секунд, `adc service stop` его завершает.
Запуск — только локальный USB с подтверждённым питанием на поддерживаемой плате.
Сначала мультиметром убедитесь, что АКБ действительно не разряжена. Повторный
start срок не продлевает. Сохранение ADC, потеря USB или тайм-аут завершают окно.

## Радио, мощность, автоанонс

| Команда | Назначение |
| --- | --- |
| `get radio` | Параметры LoRa |
| `set radio F,BW,SF,CR` | Частота в МГц, полоса в кГц, SF, знаменатель CR; через запятую без пробелов |
| `get tx` / `set tx N` | Мощность в дБм, от −9 до предела платы; `ui tx` сообщает границы |
| `get path.hash.mode` / `set path.hash.mode N` | 0 = 1 байт, 1 = 2 байта, 2 = 3 байта хеша маршрута |
| `get advert` / `set advert N` | Автоанонс: 0, 15, 30, 60, 120, 180 минут; 0 выключает |
| `get agc_reset` / `set agc_reset on` | Профилактический AGC-сброс; off выключает |
| `get fem.lna` / `set fem.lna on` | Режим усиления приёма внешнего FEM, если драйвер поддерживает переключение |
| `get fem.pa` / `set fem.pa on` | Переключаемое усиление передачи FEM, если поддерживается; не выключатель питания PA |

CR=5 означает 4/5. Радиопараметры берите из своей сети. `set radio` применяется
сразу, сохраняя TX/FEM, ретрансляцию и хеш пути. Заданный TX — не измеренная
мощность на антенне. Автоанонс — интервал, не время суток; сохранение не
отправляет анонс немедленно. AGC-сброс — экспериментальная профилактика
раз в 60 секунд с отсрочкой при активности, не перезагрузка ноды.

На T096 `caps fem.pa` возвращает `> 0`, а `set fem.pa on/off` — `Error: unsupported`.
При передаче драйвер включает FEM автоматически. `get fem.pa` может читать
неиспользуемое сохранённое значение `0`; это не измерение состояния усилителя.
Для управления приёмом на T096 используется `fem.lna`.
Различия других плат — в [матрице радио и подключения](CLI_BOARD_MATRIX_RU.md#радио-и-подключение).

Дополнительные `get KEY` / `set KEY VALUE`: `af` 0–9, `dutycycle` 10–100%
(то же поле ограничения эфирного времени), `rxdelay` 0–20, `multi.acks` 0–255,
`radio.rxgain` on/off — усиление радиочипа. `get freq` только читает частоту.

## GPS, имя и питание

| KEY / команда | Назначение |
| --- | --- |
| `gps` | Аппаратный GPS, on/off |
| `gps_source` | 0 = модуль; 1 = телефон, только если разрешён в schema |
| `gps_interval` | Интервал GPS, 0–86400 секунд; 0 не выключает GPS |
| `advert_location` | Включать местоположение в анонс, on/off |
| `get name` / `set name Дача` | Имя до 31 байта UTF-8; запрещены `[ ] \ : , ? *` |
| `get tz.offset` / `set tz.offset 6` | Часовой пояс −12…+14 с шагом 0.5; само время не меняется |
| `set pin N` | PIN Bluetooth: 0 или шестизначное число |
| `battery_protection` | on = обычный порог 3,2 В; off оставляет аварийный 2,7 В |
| `get shutdown_mv` | Настроенный порог выключения, мВ |

Строки с KEY используют `get KEY` / `set KEY VALUE`. Телефонный GPS в текущих
публичных профилях выключен. Наличие настройки не подтверждает подключение
модуля. Отключение защиты АКБ не исправляет калибровку. Во время ADC service
обычное выключение временно приостановлено, хотя сохранённый порог не меняется.

## Быстрые фразы текстом

```text
reply set 1 Да, скоро буду
reply get 1
reply reset 1
```

Слоты 1–9, до 64 байт UTF-8. Кавычки не нужны: всё после номера и одного пробела
— текст; внутренние и крайние пробелы сохраняются. Чтение своей фразы:
`> Да, скоро буду`. После reset: `OK reply slot=1 default=1` — используется
встроенная фраза. Запись/сброс: `OK reply_saved slot=1`. Это заготовка,
не отправка сообщения. Символ `|`, переводы строк и управляющие символы запрещены.

## Подключение

| Команда | Назначение |
| --- | --- |
| `get connection` | Режим, клиент, возможности и разрешение записи |
| `set connection ble` | Перейти на Bluetooth |
| `set connection usb` | Перейти на USB-компаньон |
| `set connection wifi` | Перейти на заранее настроенный Wi-Fi |
| `connection status` | Статус переключения |
| `get wifi.status` / `get wifi.ip` | Состояние Wi-Fi / адрес ноды |

`OK mode target=usb state=pending` — переключение запланировано. Нода сначала
отправляет ответ, затем меняет режим. Связь может закрыться; подключитесь новым
способом. `state=active` — нужный режим уже выбран.

Первичная настройка Wi-Fi использует `ui wifi begin`, `ui wifi ssid HEX`,
`ui wifi password HEX`, `ui wifi test`, `ui wifi status`, затем `ui wifi save`
только после `state=test_ok`. Отмена — `ui wifi cancel`. HEX не шифрует пароль.
Точные ограничения — в [контракте CLI](SMARTUI_CLI_RU.md#wi-fi-только-через-ble-или-usb).
Настройка — по BLE/USB, не через изменяемое Wi-Fi-соединение. Для ручного ввода
без HEX удобнее форма USB Helper. TCP5000 — только доверенная локальная сеть.

`board` и `ver` читают модель/версию. `caps KEY` читает возможность, например
`caps sound_preview`, `caps night_quiet`, `caps vibration`, `caps fem.lna`.
`reboot` перезапускает; `poweroff`/`shutdown` выключают поддерживаемую плату.
Они могут завершиться без ответа; SDK/командное поле Helper их не отправляют.

## Ошибки

| Код после `Error:` / `ERR ui` | Значение |
| --- | --- |
| `unsupported` | Функция отсутствует в плате/сборке |
| `invalid`, `range` | Неверный формат/значение; проверьте единицы и schema |
| `pin_conflict` | Вывод занят или запрещён |
| `busy` | Операция отклонена, устройство занято |
| `muted` | Общая тишина не разрешает операцию |
| `time` | Ночная тишина: нет достоверных часов или сейчас не ночное окно |
| `readonly`, `storage` | Изменение запрещено или не сохранено; не стирайте память |
| `source` | Нет пригодного исходного замера ADC |
| `stale` | Расчёт/этап устарел |
| `usb_required` | Нужен локальный USB с подтверждённым питанием |

## Сервисный USB и совместимость

В обычном Serial-терминале на 115200, когда на ноде выбран BLE/Wi-Fi,
используется `settings ...`, `wifi ...`, `mode ...`. В USB-компаньоне обычный
терминал не заменяет CMD66. Один порт — одна программа чтения.

Примеры: `settings get volume`, `settings set volume 7`, `settings sound preview`,
`settings adc preview 3320`, `settings adc apply TOKEN`, `settings set night_quiet 1`,
`settings set bridge 1` при поддержке. Здесь фразы сохраняют старый HEX-формат
`reply set N HEX`; новый текстовый формат относится к консоли приложения.

Старые `ui ...` сохранены для Helper и существующих клиентов. Старые
`sound_quiet` (обратный смысл к sound), `muted` (то же, что mute),
`adc.multiplier` (то же, что adc) и `test notification` остаются совместимыми.
Новые приложения используют основной синтаксис этой инструкции и `control=1`.

Все видимые настройки публичного меню покрыты группами выше: уведомления/пины,
LED/экран, радио/FEM/анонс, GPS, ADC/питание, подключение, имя/PIN/часовой пояс,
фразы и ночная тишина. Скрытые устаревшие страницы, миграции и приватные функции
не открываются. Контакты, каналы, ключи и сообщения остаются в штатном
companion-протоколе. Произвольного доступа к файлам и GPIO нет.
