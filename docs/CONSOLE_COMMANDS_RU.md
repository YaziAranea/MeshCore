# Smart UI 0.16 — команды консоли простыми словами

Эта инструкция — для **консоли своей подключённой ноды-компаньона** в приложении.
Подключитесь к ней по Bluetooth, USB-компаньону или Wi-Fi/TCP и откройте «Консоль
радио» (название зависит от приложения). Приложение должно поддерживать локальный
MeshCore CLI, команду 66 и ответ 29. Это не чат с ретранслятором и не удалённые
команды по LoRa.

## Быстрый старт

Отправляйте по одной команде и дожидайтесь ответа:

```text
ver
help
get volume
set volume 7
get volume
```

`get` читает, `set` меняет и сохраняет. Ответ `OK` — подтверждение выполнения;
`> 7` — прочитанное значение. После изменения прочитайте параметр обратно.
Отдельная команда `save` для этих настроек не нужна. Если пропал ответ,
переподключитесь и прочитайте состояние: повторять запись вслепую не нужно.

Пишите команды латиницей в нижнем регистре. Для переключателей SmartUI разрешены
`on`/`off` либо `1`/`0`; оригинальная `set radio.rxgain` принимает только `on`/`off`.
Название ноды может быть русским. Числа с дробью — с
точкой. Буквенные обозначения `N`, `TOKEN`, `F` и т. п. ниже — места для ваших
значений, а не буквальный текст команды. Служебный префикс запроса приложение
добавляет само; копировать показанное рядом с ответом `b5|` не нужно.

## Справка прямо на ноде

В 0.16 настройки перечислены ниже по группам. Для каждого скалярного параметра
можно проверить не только текущее значение, но и **разрешённые варианты именно
этой платы**:

```text
schema tone_pin
get tone_pin
```

Ответ `OK schema ... supported=1 min=... max=... step=... options=...` сообщает
поддержку и ограничения. Если `options` содержит список через запятую, выбирайте
только из него: диапазон `min/max` сам по себе не разрешает остальные значения.
`supported=0` — функция отсутствует в этой плате или сборке. `options=-` означает
обычный диапазон с указанным шагом. Ответы `schema` могут измениться после выбора
пина или мостового звука: повторно прочитайте их перед следующей перенастройкой.

### Настройки, добавленные в 0.16

Все строки таблицы читаются как `get ИМЯ`, меняются как `set ИМЯ ЗНАЧЕНИЕ`.
Обычные переключатели принимают `on/off` или `1/0`. Для числовых настроек
нужны числа. Все значения проходят проверки прошивки; помощник не обходит их.

| Имя | Назначение и значения |
| --- | --- |
| `notify_mode` | Каналы обычных уведомлений: 1 = LED, 2 = звук, 4 = вибро; складываются, 0 = без каналов. Разрешённые комбинации — в `schema` |
| `important_notify_mode` | Те же каналы для важных сообщений. Некоторые сборки уведомляют только о важных: проверяйте именно этот параметр |
| `led_pin` | Контакт внешней световой индикации из `schema led_pin` |
| `tone_pin` | Контакт звука из `schema tone_pin` |
| `vibe_pin` | Контакт вибро из `schema vibe_pin`; `-1` отключает выход |
| `melody_dm` | Мелодия личного сообщения; только сборки с отдельными мелодиями событий |
| `melody_mention` | Мелодия упоминания; то же ограничение |
| `melody_system` | Системная/основная мелодия. В сборке с одной общей мелодией меняет её для всех событий |
| `tone_8bit` | 8-битный стиль звука on/off, если поддерживается |
| `high_drive` | Усиленный режим выхода on/off, если поддерживается; как в меню, выбор устанавливает громкость 10 |
| `resonance_hz` | Резонанс: 1800, 2200, 2600, 3000, 3400, 3800 или 4200 Гц |
| `offline_dm_led` | Световое напоминание о ЛС без подключённого приложения |
| `ble_dm_led` | Световая индикация ЛС при подключённом приложении |
| `msg_popup` | Всплывающий экран сообщения on/off |
| `ui_font` | Номер шрифта: предел зависит от дисплея, узнаётся через `schema ui_font` |
| `ui_theme` | Номер темы: предел зависит от дисплея |
| `ui_top_color` | Цвет верхней области, 0–5; только цветные дисплеи |
| `ui_bottom_color` | Цвет нижней области, 0–5; только цветные дисплеи |
| `backlight_timeout` | 0 = 15 секунд, 1 = 30 секунд, 2 = 60 секунд до тайм-аута экрана |
| `gps_source` | 0 = GPS-модуль платы, 1 = координаты от телефона; только поддержанные варианты |
| `gps_interval` | Интервал аппаратного GPS в секундах, 0–86400; значение 0 не означает выключение GPS |
| `advert_location` | Разрешать включение местоположения в анонс, on/off |
| `profile` | 0 = свой, 1 = тихий, 2 = улица, 3 = ночь; только сборки с профилями |

Номера шрифтов/тем/цветов — внутренние индексы конкретного дисплея, не одинаковые
картинки на всех платах. Для выбора без запоминания номеров удобнее помощник.
`profile` применяет группу настроек, поэтому после него перечитайте звук, LED,
тайм-аут и тему. Изменение отдельной расширенной настройки возвращает «свой» профиль.
В обычной публичной сборке часть условных возможностей, например раздельные мелодии
или профили, может быть выключена: команда честно сообщает `unsupported`.

### Как выбрать пин и ничего не перепутать

```text
schema led_pin
schema tone_pin
schema vibe_pin
get led_pin
get tone_pin
get vibe_pin
```

Это **Arduino-номера пинов из конкретной прошивки**, не арифметический номер
`P0.xx/P1.xx` и не порядковый контакт разъёма. Помощник получает список от платы.
Не копируйте номера T114 в ProMicro или ESP32. Смена настройки не заменяет
правильное подключение оборудования: мотор нельзя питать непосредственно от GPIO,
а светодиоду нужен подходящий ограничитель тока.

После просмотра списка: `set tone_pin N`, затем `get tone_pin` (подставьте
разрешённый номер вместо `N`). Нельзя одновременно назначить один контакт свету,
звуку и вибро. GPS, LoRa, дисплей и мостовой выход резервируют свои линии.
`Error: pin_conflict` означает, что выбранный контакт сейчас недоступен;
перечитайте `schema`, а не пытайтесь записать его повторно.

### Быстрые фразы через CLI

В 0.16 фразы доступны в обоих USB-режимах и в локальной консоли приложения:

```text
ui reply get 1
ui reply set 1 d094d0b0
ui reply get 1
ui reply set 1 -
```

В примере HEX `d094d0b0` — русское «Да» в UTF-8. Слоты 1–9, максимум 64 **байта**,
а не 64 русские буквы. `-` снимает своё переопределение и возвращает стандартную
фразу. Чтение возвращает `OK ui reply slot=1 hex=...`; сохранение —
`OK ui reply_saved slot=1`. Это настройка фразы, она **не отправляет сообщение**.
Без HEX проще: откройте редактор фраз в USB Helper.

В обычном Serial-терминале вместо `ui reply ...` используйте прежнее `reply ...`.

### Что сознательно не открывается

CLI управляет доступными пользовательскими настройками публичной сборки.
Служебные поля миграции, удалённое «Избранное», внутренние таймеры, приватная
ретрансляция и произвольные GPIO/файлы не становятся пользовательскими командами.
Контакты, сообщения и ключи остаются в штатном companion-протоколе MeshCore;
эти операции не нужно дублировать текстовыми командами.

```text
help
help sound
help fem
help adc
help radio
help connection
help system
help advert
help led
help gps
help pins
help display
help profile
help replies
```

Один ответ ограничен 156 байтами, поэтому справка короткая и разделена по темам.
Если ответ предлагает следующую страницу, отправьте указанную команду. Полная
русская справка — этот файл. Ответ `Unknown command` на `help` при работающих
`board`/`ver` может означать старую прошивку: сама поддержка этих двух команд ещё
не подтверждает расширенную консоль 0.16.

## Информация и возможности

| Команда | Что узнаём |
| --- | --- |
| `board` | Модель платы |
| `ver` | Версия SmartUI и базовой прошивки |
| `get name` | Имя ноды |
| `get battery` | Напряжение аккумулятора в **милливольтах**, например 4100 = 4,1 В |
| `caps vibration` | Есть ли поддержка вибро в сборке |
| `caps fem.lna` / `caps fem.pa` | Есть ли управление соответствующей частью FEM |
| `caps adc` | Есть ли калибровка ADC |
| `caps adc_min` / `caps adc_max` | Нижний и верхний предел коэффициента |
| `caps melody_max` | Наибольший номер мелодии |

Также работают `get caps KEY` и прежние `ui caps KEY`. У прежних `ui` имена
другие: `ui caps fem_lna`, `ui caps fem_pa`, `ui caps bridge`, без точек.
Поддержка в сборке не
доказывает, что внешний вибромотор, зуммер или GPS физически подключён. Если
оборудования нет, команда может вернуть `Error: unsupported`.

## Громкость, вибро, тишина и мелодии

| Читать | Изменить | Значение |
| --- | --- | --- |
| `get volume` | `set volume 7` | Громкость 1–10; ноль не используется |
| `get vibration` | `set vibration on` | Вибро on/off |
| `get sound_quiet` | `set sound_quiet on` | on **отключает звук**; off разрешает его |
| `get muted` | `set muted on` | Общая тишина для уведомлений; off отменяет её |
| `get melody` | `set melody 2` | Номер от 0 до `caps melody_max` |
| `get sound.bridge` | `set sound.bridge off` | Мостовой выход звука |

```text
melodies
melody 2
set melody 2
test notification
```

`melodies` показывает текущую мелодию и максимальный номер. `melody 2` читает
название, **не проигрывает и не выбирает**. `set melody 2` сохраняет выбор для
уведомлений, включая ЛС, упоминания и системные сигналы. `test notification`
запускает обычное уведомление с сохранёнными настройками. Общая тишина и
отключённые каналы при этом учитываются: `OK` не доказывает, что физический
зуммер прозвучал.

Для проверки звука убедитесь, что `muted` выключен, `sound_quiet` выключен,
громкость ненулевая и зуммер подключён. Не меняйте чужие настройки ради теста.

### Прослушать мелодию без изменения каналов уведомлений

В обновлённой 0.16 есть отдельная команда. В локальном CLI приложения или
USB-компаньона сначала проверьте поддержку:

```text
ui caps sound_preview
ui sound preview
```

Первый ответ: `OK ui caps key=sound_preview value=1`. Это только чтение;
оно не запускает звук. Второй ответ при успешном запуске: `OK ui sound_preview`.
В сервисной USB-консоли используйте `settings caps sound_preview` и
`settings sound preview`; ответы начинаются с `OK settings`.

Команда проигрывает **сохранённую** мелодию с сохранёнными громкостью и выводом.
Несохранённый выбор в помощнике не используется. Маска уведомлений и `sound_quiet`
не мешают прослушиванию; **общая тишина `muted=1` запрещает запуск**.
Flash, GPIO-настройки, каналы уведомлений и вибрация командой не перенастраиваются.
`OK` означает принятие запуска, а не физическую проверку излучателя.

Возможные отказы: `muted`, `busy`, `pin_conflict`, `unsupported`, `readonly`.
Формат — `ERR ui ПРИЧИНА` или `ERR settings ПРИЧИНА`. Не снимайте общую тишину
автоматически и не повторяйте запуск при потерянном ответе. Если ключ возможности
не распознан или равен 0, нужна свежая сборка: номер `0.16` сам по себе поддержку
не доказывает. На T114 обновление UF2 выполняется поверх, без Erase.

В Helper 2.3 это вкладка **«Звук и пины»**: сначала «Считать звук и пины с ноды»,
затем прослушивание. «Проверить уведомление» остаётся отдельной проверкой;
при режиме только LED тишина в ней ожидаема.

**Мост — не сетевой мост и не передача аудио.** Это электрический способ
управления совместимым плавающим пьезоизлучателем между двумя штатными выводами.
Нельзя соединять такой выход с землёй или произвольно подключённой нагрузкой.
Включать `sound.bridge` следует только при подходящей схеме.

## FEM и мощность передачи

```text
get fem.lna
set fem.lna on
get fem.pa
set fem.pa on
get tx
set tx 20
get tx
```

LNA — малошумящий усилитель приёма. PA — усилитель передачи. Это два независимых
переключателя на поддерживаемых платах; команда FEM не добавляет отсутствующее
оборудование. Изменение во время занятого радио может вернуть `Error: busy`:
дождитесь освобождения радио, затем повторите **отклонённую** команду.

`set tx` принимает целое число дБм от −9 до максимума конкретной сборки.
Недопустимое значение отклоняется, не заменяется молча максимальным. Значение
параметра прошивки не является измерением мощности на антенне: внешний FEM и
радиотракт влияют на результат. Используйте разрешённые для вашего оборудования
и места параметры; программный диапазон не заменяет эти ограничения.

## ADC: прочитать, ввести коэффициент или рассчитать

Привычное название команды такое же, как в CLI ретранслятора:

```text
get adc.multiplier
caps adc_min
caps adc_max
```

Короткие `get adc` и `set adc …` — синонимы. Здесь «ADC» — коэффициент измерения
напряжения, не частота опроса и не значение в вольтах.

### Способ 1. Коэффициент уже известен

```text
set adc.multiplier 1.815000
get adc.multiplier
```

**1.815000 — только пример синтаксиса.** Нужен проверенный коэффициент именно
вашей платы. Используется положительное число с точкой, до шести знаков после
точки; диапазон — `adc_min`…`adc_max` (75–125% заводского коэффициента).
Прямой ввод не требует предварительного измерения без USB. Значения `NaN`,
`Inf`, экспонента, отрицательные числа и ноль не принимаются.

Отличие от некоторых ретрансляторных прошивок: **ноль не означает сброс**.
Для возврата заводской калибровки есть отдельная команда:

```text
adc reset
```

### Способ 2. По мультиметру

1. Измерьте напряжение непосредственно на аккумуляторе.
2. Если мультиметр показывает 3,32 В, отправьте `adc preview 3320`.
3. Проверьте `sampled_mv`, `measured_mv` и рассчитанный `multiplier` в ответе.
4. Возьмите число из поля `token` и отправьте `adc apply TOKEN`.
5. Прочитайте `get adc.multiplier` и проверьте напряжение от аккумулятора.

`preview` не сохраняет коэффициент. Принимается 2500–4500 мВ; расчёт также
должен укладываться в диапазон коэффициента. Токен действует менее 60 секунд.
Не меняйте исходную калибровку между расчётом и применением.

**ProMicro:** USB может искажать ADC. Для расчёта нужен замер от АКБ не старше
двух минут: включите ноду от аккумулятора, дождитесь показания, подключите USB
без перезапуска. Через Bluetooth можно получить замер, не подключая USB.
`Error: source` означает отсутствие пригодного замера, а не плохой пароль.

### Если нода выключается до калибровки

```text
adc service
adc service start
adc service stop
```

Это дополнительное сервисное окно до 120 секунд, **только через локальный USB
с подтверждённым USB-питанием на поддерживаемой плате**. Одного Bluetooth или
Wi-Fi недостаточно. Оно временно приостанавливает обычное выключение по
показанию ADC, но не исправляет измерение. Повторный start срок не продлевает.
Отключение USB, сохранение ADC, перезапуск, stop и тайм-аут возвращают защиту.

Сначала убедитесь мультиметром, что аккумулятор действительно не разряжен.
Не используйте коэффициент или сервисное окно для обхода реальной проблемы
питания. Защита 3,2/2,7 В и ошибки хранилища сохраняются.

## Радио, автоанонс и AGC

В Helper 2.3 длина хеша выбирается во вкладке «Радио и хеш» → «Хеш маршрута»:
1, 2 или 3 байта. В CLI `path.hash.mode` использует индексы 0, 1, 2 соответственно;
например, `set path.hash.mode 0` выбирает один байт. После записи проверьте
`get path.hash.mode`. Помощник меняет только длину хеша, сохраняя остальные
прочитанные с ноды радиопараметры.

```text
get radio
get freq
set radio F,BW,SF,CR
get advert
set advert 60
get agc_reset
set agc_reset on
```

Для `set radio` частота **в МГц**, полоса **в кГц**, SF и знаменатель CR —
целые числа. Параметры разделены запятыми, без пробелов. Это другой формат,
чем машинная команда `ui radio set` с кГц/Гц. Команда сохраняет текущую длину
хэша пути и не меняет TX/FEM/ретрансляцию. Применяется сразу; в случае отказа
прошивка пытается восстановить прежние параметры. Частоту выбирайте по своей
сети, а не по чужому примеру.

Автоанонс: **0, 15, 30, 60, 120, 180 минут**. Ноль выключает. Это интервал, не
время суток. Сохраняется тот же таймер, что в меню; немедленный анонс не
отправляется. Используется прежний локальный zero-hop анонс.

AGC — экспериментальная профилактика приёма каждые 60 секунд с отсрочкой при
активности радио. По умолчанию выключена. Это не перезапуск ноды и не гарантия
исправления потери связи; на время процедуры есть короткий перерыв приёма.

Дополнительные радиокоманды для понимающих их назначение:

| Чтение / запись | Диапазон |
| --- | --- |
| `get af` / `set af N` | 0–9, коэффициент алгоритма эфирного времени |
| `get dutycycle` / `set dutycycle N` | 10–100%; изменяет тот же `af` |
| `get rxdelay` / `set rxdelay N` | 0–20, параметр задержки приёма |
| `get multi.acks` / `set multi.acks N` | 0–255 |
| `get path.hash.mode` / `set path.hash.mode N` | 0, 1, 2 → 1, 2, 3 байта хэша |
| `get radio.rxgain` / `set radio.rxgain on` | Усиление самого приёмника, не внешний FEM |

`dutycycle` — параметр алгоритма прошивки, не гарантия соблюдения региональных
ограничений использования эфира. Настройки `cad`, `int.thresh`,
`agc.reset.interval`, `txdelay`, `direct.txdelay` не реализованы.

## LED, GPS, имя, часовой пояс, PIN

```text
get board_led
set board_led off
get unread_led
set unread_led on
get gps
set gps on
set name Дача
get name
get tz.offset
set tz.offset 6
```

LED платы и LED напоминаний — разные настройки. GPS означает аппаратный
источник и требует подключённого модуля. Часовой пояс — от −12 до +14 часов,
шаг полчаса; эта команда не устанавливает само текущее время.

`set name` — до 31 байта UTF-8, запрещены `[ ] \ : , ? *`. Русские буквы
занимают больше одного байта. `set pin N` задаёт 0 либо шестизначное число;
меняйте PIN только осознанно, поскольку он влияет на Bluetooth-подключение.
Не отправляйте скриншоты с PIN и не записывайте его в публичный журнал.

`get battery_protection` / `set battery_protection on` управляют защитой:
on — 3,2 В, off — остаётся аварийный порог 2,7 В. Отключение не рекомендуется
как способ исправить неверную калибровку.

## Подключение, Wi-Fi и перезапуск

```text
get wifi.status
get wifi.ip
ui connection
ui mode status
```

Смена подключения: `ui mode ble`, `ui mode usb`, `ui mode wifi`. После ответа
текущий канал может закрыться; подключитесь выбранным способом. Wi-Fi должен
быть настроен заранее. Для сети используйте отдельную форму помощника либо
[проверяемый сценарий `ui wifi`](SMARTUI_CLI_RU.md#wi-fi-только-через-ble-или-usb).
Пароль не читается обратно. `set wifi.*` не заменяет этот сценарий.

`reboot` перезапускает, `poweroff`/`shutdown` выключает поддерживаемую плату.
Успешная операция может не прислать ответ. Само отключение связи не доказывает
успеха; эти команды намеренно не доступны в SDK/командном поле помощника.

Wi-Fi/TCP — только доверенная локальная сеть, порт 5000 без отдельной
аутентификации/TLS. Не открывайте этот порт в интернете.

## Где какой синтаксис работает

1. **Консоль радио приложения:** команды этой инструкции через CMD66/RESP29.
2. **Помощник 2.3, «Настройки (USB-компаньон)» → «Консоль и файлы»:** поддержанные
   команды чтения и подтверждённого изменения. Для ADC и Wi-Fi используйте
   специальные формы. Значения PIN и секреты в это поле не вводятся.
3. **PuTTY / обычный Serial-терминал:** на ноде выбран BLE или Wi-Fi; это прежняя
   сервисная консоль. Используются `settings get`, `settings set volume 7`,
   `settings adc set …`, `settings radio`, `settings advert set 60`, `wifi setup`.
   Новые короткие `get/set` автоматически в этот порт не переносятся.

Подмена `ui` на `settings` работает не для всех функций. Например, AGC/FEM/мост
доступны через companion CLI, а не через сырой сервисный `settings set`.
Один COM-порт в каждый момент должна читать одна программа.

## Если пришла ошибка

| Ответ | Что делать |
| --- | --- |
| `Error: unsupported` | Проверить `caps`: плата/сборка не поддерживает функцию |
| `Error: invalid` / `range` | Проверить синтаксис, единицы и допустимый диапазон |
| `Error: busy` | Дождаться завершения текущей операции; отклонённая запись не применена |
| `Error: readonly` / `storage` | Не стирать память. Прочитать состояние и сообщить версию/build |
| `Error: source` | ADC: получить пригодный замер от аккумулятора |
| `Error: stale` | ADC: сделать новый расчёт, старый токен устарел |
| `Error: usb_required` | Сервисному окну нужен подтверждённый локальный USB |
| `Unknown command` | Проверить написание, выбранный вход и установленную сборку |
| Нет ответа | Результат неизвестен. Переподключиться, прочитать состояние; не повторять запись автоматически |

Для разработчиков: `smartui_cli:1`, затем `ui hello`; расширение коротких команд
обозначается **`console=1`**, оригинальные имена MeshCore — **`meshcore=1`**.
Сохранены старые `ui …`; архивный API201, sync/events и выполнение удалённых
LoRa-команд не включались. [Полный транспортный контракт](SMARTUI_CLI_RU.md).
