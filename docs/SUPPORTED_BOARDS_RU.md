# Поддерживаемые платы

Текущий публичный выпуск `smartui-0.20` содержит восемь конфигураций: семь прежних и отдельную ProMicro/FakeTec V4 без экрана. Официальная база MeshCore 1.18.0 — `81dbae59`, дополнения PowerSaving сохранены; [решения переноса](MIGRATION_1.18_RU.md). Совпадение процессора само по себе недостаточно: должны совпадать радиомодуль, распайка, измерение АКБ и управляющие линии.

На всех семи платах страница `Дополнительно → Калибр. АКБ` меняет реальный коэффициент ADC. Значение сохраняется только после подтверждения. Калибровка требует мультиметра: multiplier исправляет масштаб, но не аппаратный offset.

В 0.20 те же основные настройки доступны через [USB-помощник 2.9](../tools/usb-helper/README_RU.md), без экранного меню: сервисная консоль либо локальный Companion CLI. Наличие дисплея для протокола USB-настроек не требуется. ADC можно рассчитать по мультиметру либо напрямую ввести известный коэффициент своей платы. Зуммер, LED, вибромотор и GPS помощник предлагает по возможностям профиля; это не физическое обнаружение внешнего модуля. Доступные команды, ограничения и различия плат: [матрица CLI](CLI_BOARD_MATRIX_RU.md). Для четырёх ESP32: [внешний зуммер](EXTERNAL_BUZZER_RU.md).

## Работа без дисплея

1. Обычные релизные файлы сохраняют экранный UI. Если драйвер не смог подключить дисплей, уведомления и защита АКБ продолжают обслуживаться. SPI-дисплеи не всегда позволяют определить физическое отсутствие панели — флаг в помощнике показывает подключённый драйвер, а не достоверную аппаратную диагностику.
2. Для гарантированного отключения инициализации дисплея при сборке из исходников используйте профили `SmartUI_T096_headless`, `SmartUI_T114_headless`, `SmartUI_ProMicro_headless`, `SmartUI_V3_headless`, `SmartUI_V43_headless`, `SmartUI_Paper_headless`, `SmartUI_V43_R8_headless` из `platformio.smartui-headless.ini`. Например: `pio run -e SmartUI_ProMicro_headless -t create_uf2`.
3. Эти профили наследуют распайку, радио и питание соответствующей основной платы. Они не относятся к старым upstream-целям `*_without_display_*` и не добавляют поддержку произвольной платы без экрана. Для `SmartUI_ProMicro_headless` в 0.20 опубликован готовый UF2; остальные headless-профили собираются из исходников. ProMicro и Paper проверяются CI.
4. Не удаляйте `DISPLAY_CLASS` вручную: в текущей архитектуре вместе с ним компилируется задача, обслуживающая уведомления и защиту батареи. `SMARTUI_HEADLESS=1` отключает именно дисплей, сохраняя эту задачу.

В семи профилях с работающим дисплеем активный BLE PIN открывается одним переходом вперёд с часов. Страница доступна и после подключения, и при выбранном USB/Wi-Fi или выключенном Bluetooth. Просмотр не меняет PIN, настройки или режим подключения; обычные таймауты экрана и возврата на часы сохраняются. При подсказке `Включите BLE` откройте `Настройки → Система → Подключение`, выберите `BLE` и подтвердите смену режима. Случайный PIN, созданный при отсутствии сохранённого кода и успешно запущенном драйвере дисплея, сохраняется между обычными перезагрузками. Для ProMicro/FakeTec Headless без прежних настроек PIN — `123456`; после обновления остаётся прежний сохранённый код. [Порядок BLE-подключения, включая чтение неизвестного PIN по USB](FLASHING_RU.md#первое-подключение-ble).

Защита АКБ включена по умолчанию с порогом 3,2 В. При выключении остаётся нижний порог 2,7 В; сохранённый выбор пользователя не перезаписывается. Это программная отсечка по ADC, не замена аппаратной защиты. Статус проверки текущего выпуска см. в [примечаниях 0.20](../RELEASE_NOTES_SmartUI_0.20_RU.md).

## Heltec T096 FEM ON

- Экран: 160×80, драйвер семейства ST7735.
- UI использует встроенные bitmap-шрифты; обычная 5×7-симуляция для этой платы неверна.
- Передающий тракт FEM включается автоматически при передаче. `fem.pa` не поддерживается: это настройка программно переключаемого TX gain, а не общий выключатель усилителя.
- По умолчанию `LORA_TX_POWER=9`: комментарий аппаратного профиля оценивает это примерно как 22 dBm после усилителя.
- `MAX_LORA_TX_POWER=22` относится к настройке выхода SX1262, а не к гарантированно измеренной мощности на разъёме антенны. При внешнем FEM фактический EIRP может быть существенно выше.
- RX gain FEM включён по умолчанию; `fem.lna` управляет усилением при приёме. Название `FEM ON` не означает поддержку команды `set fem.pa on`. Ответ `0` на `get fem.pa` — значение поля настроек, а не признак физически выключенного PA.
- В целевой сборке есть аппаратный GPS.
- Цель собирается с `-Os`: это сохраняет extra-FS и все 15 публичных шрифтов.

Нельзя прошивать T096-файлом другую T96-подобную плату без сверки распайки и FEM. Не включайте передачу без согласованной антенны.

## Heltec T114 с дисплеем

- Готовый релизный UF2 предназначен для конфигурации с цветным дисплеем.
- Физическая матрица: 240×135.
- Драйвер строит интерфейс в логических координатах 128×64 и масштабирует его с коэффициентами `1.875 × 2.109375`, `Y_OFFSET=1`. Именно эта особенность учитывается в точной симуляции.
- В целевой сборке есть аппаратный GPS.
- Настроенная мощность SX1262 по умолчанию — 22 dBm.
- Цель собирается с `-Os`; это уже прописано в `variants/heltec_t114/platformio.ini`.

Файл не предназначен для других аппаратных конфигураций из upstream-целей `Heltec_t114_without_display_*`. Для работы без панели при сохранении распайки поддерживаемой T114 есть собственная сборка `SmartUI_T114_headless`, описанная выше; готовый headless-UF2 не публикуется.

## ProMicro nRF52840 + Heltec RA62

Поддерживается конкретная схема:

- плата ProMicro/SuperMini на nRF52840;
- радиомодуль Heltec RA62 на SX1262;
- SSD1306 OLED 128×64 по I²C;
- пользовательская кнопка UI на D6/GPIO6.

В документации D6 означает не кнопку Reset и не встроенную кнопку любой случайной ProMicro. Это физическая пользовательская кнопка, электрически соединённая с выводом D6 целевого проекта. Она листает экраны и будит дисплей.

Внешний UART/NMEA GPS, добавленный в 0.05, сохранён в том же UF2 0.20 и по умолчанию выключен.
GPS TX подключается к P0.20 (логический D3), GPS RX — опционально к P0.22 (D4).
Нужны общая земля, безопасное питание и сигнальные уровни 3,3 В.
[Подключение, питание, статусы и ограничения GPS](PROMICRO_GPS_RU.md).

Компактный OLED не включает неиспользуемые крупные шрифтовые таблицы. Пять пиксельных стилей сохранены. Размер нужно проверять по отчёту линковщика конкретного выпуска.

SmartUI V5 отключает автономный BLE connection LED до `Bluefruit.begin()`,
не отключая BLE. `LED платы: ВЫКЛ` запрещает штатную индикацию/TX/уведомление
на встроенном GPIO. Исправленный UF2 V5 с внутренним маркером `LED2` закрывает
и обход выключателя через flash/cache, не отключая сохранение данных.
Та же поправка включена в T114/T096 и сохранена в 0.20; текущий внутренний маркер — `SmartUI 0.20`.

## ProMicro / FakeTec V4 без дисплея

Файл: **`ProMicro_FakeTec_RA62_Headless_UI_0.20.uf2`**. Environment:
`SmartUI_ProMicro_headless`. Это стандартная схема nRF52840 ProMicro/SuperMini
с Heltec HT-RA62/SX1262 и TCXO 1,8 В. Экран не инициализируется; обслуживание
уведомлений, питания, CLI и ADC сохраняется.

Сверены линии радио: NSS P1.13, SCK P1.11, MOSI P1.15, MISO P0.02,
DIO1 P0.10, BUSY P0.29, RESET P0.09, RXEN P0.17, питание P0.13;
измерение аккумулятора — P0.31. Это физические обозначения портов nRF52840,
а не значения `led_pin`/`tone_pin` в CLI. Их логическую нумерацию сообщает `schema`.

[Проект FakeTec V4](https://github.com/gargomoma/fakeTec_pcb/issues/16) использует
три MOSFET для внешнего оборудования. Их наличие не означает, что на конкретной
сборке установлены зуммер, LED, GPS или вибромотор. Назначайте выводы под свою
распайку; недопустимые и занятые GPIO отклоняются. Коэффициент ADC зависит от
установленного делителя и проверяется мультиметром.

**Первое BLE-подключение без прежних настроек: PIN `123456`.** Выберите ноду
в совместимом приложении на телефоне и введите код при запросе. Компьютер не нужен.
При обновлении, в том числе с OLED на headless, остаются прежний сохранённый PIN
и выбранный транспорт. Обычная перезагрузка PIN не меняет.

Неизвестный PIN прочитайте через USB Helper 2.9 на компьютере: нажмите
**«Подключить ноду»**, выберите порт и дождитесь чтения. Затем откройте
**«Расширенное» → «Подключение» → «Показать PIN»**. BLE-сопряжение для этого не требуется. Чтение не меняет код
или выбранный транспорт; чтобы включить Bluetooth, используйте отдельную кнопку
во вкладке «Подключение» и подтвердите смену.

В локальном Companion CLI доступен `get pin`; в сервисной USB-консоли та же
команда выдаёт `BLEPin v=1 pin=123456`. Здесь `123456` совпадает с начальным кодом
чистого headless-профиля, но после обновления или явной смены цифры могут быть другими.
Не стирайте данные ради неизвестного PIN. [Пошаговая инструкция](FLASHING_RU.md#первое-подключение-ble).

Старый запрет FakeTec в документации до 0.20 относился к отсутствию отдельного
проверенного релизного файла. Он не является причиной прошивать случайный UF2:
другие радиомодули, варианты без TCXO и изменённая распайка требуют своей цели.

## Heltec WiFi LoRa 32 V3 OLED


- Требуется V3 с встроенным SSD1306 OLED 128×64; не Wireless Stick и не V2.
- Полный компактный SmartUI: пять пиксельных стилей, часы, чат/ЛС, клавиатура,
  адресная отправка и меню настроек.
- Пользовательская кнопка **PRG/BOOT на GPIO0**, не отдельная кнопка RST.
  При обычной работе она управляет UI; удержание GPIO0 при сбросе включает
  штатный загрузчик ESP32-S3.
- OLED: SDA GPIO17, SCL GPIO18, reset GPIO21. VEXT управляется GPIO36;
  этот профиль не переносит схему питания Wireless Paper и не меняет драйвер платы.
- Измерение АКБ: ADC GPIO1, управление делителем GPIO37; штатный коэффициент
  `5.42`, полярность ADC_CTRL определяется существующим драйвером при запуске.
  Перед оценкой порогов защиты сравните показания с мультиметром.
- Встроенный TX LED GPIO35 может использоваться уведомлениями. `LED платы: ВЫКЛ`
  блокирует его и для LoRa TX, и для уведомлений; радиопередача при этом работает.
- GPS и FEM/LNA в этом профиле не поддерживаются. Внешний звук настраивается через `tone_pin` (GPIO4/40/41; по умолчанию −1). GPIO40/41 нельзя одновременно подключать к внешнему JTAG.
- Встроенный вибромотор не заявлен. Внешний можно настроить через `vibe_pin` из разрешённого списка GPIO; доступность вибрации после назначения пина не подтверждает наличие подключённого мотора.
- Сохраняются штатные SX1262/TCXO-настройки V3 и мощность SX1262 по умолчанию 22 dBm.
- Нужны отдельные **V3** merged/update BIN. Файлы V4.3, Paper и UF2 не подходят.

Совпадение OLED-геометрии с ProMicro/V4.3
не является аппаратным испытанием питания, радио или пробуждения V3.

## Heltec V4.3 OLED FEM ON

- Поддерживается именно OLED 128×64, не V4 TFT.
- Аппаратный GPS включён; состояния GPS и значок тишины разведены с группой АКБ в реальной OLED-геометрии.
- RX gain FEM включён по умолчанию через `RADIO_FEM_RXGAIN=1`; `fem.lna` доступен при определении KCT8103L, но недоступен для GC1109 — проверяйте `caps fem.lna`. Передающий тракт включается автоматически при TX; `fem.pa` не поддерживается. Ответ `0` на `get fem.pa` не означает, что физический PA выключен.
- Встроенный зуммер не заявлен. Внешний настраивается через `tone_pin` (GPIO4/47/48; по умолчанию −1). GPIO40/41 зарезервированы под GPS.
- ESP32-S3 требует BIN, а не UF2: merged для чистой установки/Web Flasher и update для обновления приложения.

## Heltec V4 R8 OLED FEM ON

- Отдельная плата **WiFi LoRa 32 V4-R8**, не обычная V4.3 R2. ESP32-S3R8, 8 МБ octal PSRAM, 16 МБ flash; сборка использует `qio_opi` / `opi`.
- Поддерживается OLED SSD1306 128×64: SDA17, SCL18, reset21. Пять компактных шрифтов, часы, меню, клавиатура и выбор адресата — общий OLED-интерфейс. Цветной TFT R8 не включён в этот релиз.
- Пользовательская кнопка **PRG/BOOT, GPIO0**; RST только перезагружает плату.
- Общая линия Vext — **GPIO40, активный LOW**. Пока радио работает, прошивка сохраняет питание линии даже при выключенном OLED. Полное выключение отдельно переводит FEM и периферию в отключённое состояние.
- SX1262: NSS8, SCK9, MOSI10, MISO11, DIO1=14, BUSY13, RESET12. FEM KCT8103L: CSD2, CTX5, питание7. LNA по умолчанию включён; `fem.lna` управляет усилением при приёме. Передающий тракт FEM включается автоматически при TX; `fem.pa` не поддерживается. Ответ `0` на `get fem.pa` не означает, что физический PA выключен.
- Встроенный LED — **GPIO46** по схеме V4.3.2; общий выключатель `LED платы` распространяется на TX-индикацию. GPIO35–37 заняты PSRAM, их нельзя использовать по схеме старой R2.
- АКБ измеряется на **ADC GPIO1**, отдельного `ADC_CTRL` нет. Делитель 390 кОм / 100 кОм, базовый коэффициент с поправкой — `5.0715`. Возможна калибровка по мультиметру через меню/помощник.
- Внешний GPS/NMEA: RX платы38, TX39, управление питанием42 (LOW). Это поддержка подключённого модуля, не обещание встроенного GPS во всех комплектациях. Отдельный reset GPS на GPIO42 не используется: это линия питания. Применяйте подходящий модуль/шлейф Heltec и проверяйте напряжения.
- Bluetooth, USB-компаньон, Wi-Fi и сервисная USB-консоль сохранены. Внешний зуммер настраивается через `tone_pin` (GPIO4/6/15/16/47/48; по умолчанию −1). Вибромотор подключается через драйвер и отдельный допустимый `vibe_pin`; наличие устройств не определяется.
- Файлы: **`Heltec_V4_R8_UI_0.20-merged.bin` / `Heltec_V4_R8_UI_0.20-update.bin`**. Помощник определяет `Heltec V4 R8 OLED`; файл R2 отклоняется при проверке. Предыдущих SmartUI-файлов R8 в 0.12 нет.

Источники: [карточка Heltec](https://heltec.org/project/wifi-lora-32-v4/), [официальная документация R8](https://github.com/HelTecAutomation/HeltecWiKi/blob/main/docs/devices/open-source-hardware/esp32-series/lora-32/wifi-lora-32-v4_r8_board/wifi-lora-32-v4_r8_board.md), [схема HTIT-WBR8H V4.3.2](https://resource.heltec.cn/download/WiFi_LoRa_32_V4-R8/Schematic/HTIT-WBR8H_V4.3.2.pdf). Схема и Wiki указывают LED46; отличающееся старое определение LED45 в Arduino-варианте не копировалось.

Проверки конфигурации, сборка и OLED-симуляция не заменяют физического испытания R8: подключение, TX/RX, сон/пробуждение, GPS и ADC нужно подтвердить на устройстве. Мощность на антенном разъёме не измерялась; значение SX1262 не равно гарантированной мощности после FEM.

## Heltec Wireless Paper

- Физическая матрица: 250×122, 1-bit e-paper.
- Одна сборка `FULL`: часы, чат, ЛС, настройки, клавиатура и target picker. Лесной фон убран. Каждое движение курсора обновляет e-paper; полный refresh выполняется периодически против ghosting.
- GPIO45/VEXT питает одновременно дисплей и LoRa-тракт. Поэтому `AUTO_OFF_MILLIS=0`; обычное OLED-выключение дисплея способно обесточить радио.
- GPIO0 — пользовательская кнопка, GPIO18 — TX LED. Их нельзя выдавать за tone pin.
- GPS, FEM и вибрационный выход в публичном профиле Paper FULL не поддерживаются. Внешний звук доступен на GPIO17/21; исходный `tone_pin=-1`. GPIO15/16 заняты кварцем. Переназначение LED и `vibe_pin` недоступно; штатный TX LED управляется через `board_led`.
- Заявлены ревизии с поддерживаемым определением BUSY polarity; Wireless Paper V1.0 не заявлен.
- PIN-страница открывается вручную, остаётся доступной после связи и не заменяет обычные часы в idle-режиме.

## Что не поддерживается

- FakeTec с иной распайкой или радиомодулем; старое имя environment `ProMicro_faketac_htra62_companion_radio_ble` не является целью этого выпуска.
- Heltec V4/V4 R8 TFT и другие ESP32-S3-платы вне четырёх точных профилей V3 OLED, V4.3 OLED R2, V4 R8 OLED и Wireless Paper FULL.
- Другие аппаратные конфигурации T114 из upstream-целей `Heltec_t114_without_display_*`. Собственная `SmartUI_T114_headless` сохраняет распайку поддерживаемой T114; готового headless-файла нет.
- T096 FEM OFF.
- Любая ProMicro с другой распайкой OLED, кнопки или RA62.
- Репитерные, room server, USB-only и sensor environments.

Исходный MeshCore содержит много других вариантов, но наличие их конфигураций в дереве не превращает их в часть релиза. Старый `Heltec_v3_companion_radio_ble` сохранён отдельно: для полного SmartUI нужен environment с суффиксом `_smartui`. Xiao S3 WIO/T1 в CI служат только проверке компиляции общих display-драйверов. Для T1 используется USB-цель `Heltec_t1_companion_radio_usb`; обе companion-цели T1 собираются с `-Os` в штатной ExtraFS-разметке, но готовые файлы T1 не публикуются. RAK4631 не входит в обязательную матрицу. Это не расширяет поддержку Release; [подробности](BUILD_RU.md#целевые-сборки).

## Как убедиться, что файл выбран правильно

Перед прошивкой сравните сразу три вещи:

1. Полное название платы и установленного радиомодуля.
2. Environment и формат файла: UF2 нельзя путать с merged/update BIN.
3. SHA-256 из манифеста того же Release/CI-артефакта: `SHA256SUMS.txt` для UF2 или `SHA256SUMS-ESP32.txt` для development BIN.

Для ProMicro/FakeTec выбирайте OLED или headless по наличию дисплея и сверяйте распайку. V4 OLED и TFT, а также V4 R2 и R8 требуют разных аппаратных профилей.
