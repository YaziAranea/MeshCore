# Внешний зуммер на ESP32: SmartUI 0.18+

В готовых сборках **V3 OLED, V4.3 OLED R2, V4 R8 OLED и Wireless Paper FULL**
можно назначить вывод внешнего зуммера без пересборки прошивки. Настройка
сохраняется после перезагрузки. По умолчанию выход выключен: `tone_pin=-1`.
На T096/T114/ProMicro сохраняется прежний звуковой профиль.

## Подключение и выбор GPIO

| Плата | Возможные выводы звука |
| --- | --- |
| Heltec V3 OLED | GPIO4, GPIO40, GPIO41 |
| Heltec V4.3 OLED R2 | GPIO4, GPIO47, GPIO48 |
| Heltec V4 R8 OLED | GPIO4, GPIO6, GPIO15, GPIO16, GPIO47, GPIO48 |
| Wireless Paper FULL | GPIO17, GPIO21 |

Это исходный список. **Перед подключением прочитайте `schema tone_pin`:**
вывод, назначенный LED или вибрации, исключается из `options`. Номера здесь —
номера GPIO ESP32, а не позиции контактов разъёма. Используйте свободный вывод
точной модели платы; собственные подключённые устройства прошивка не обнаруживает.
На V3 GPIO40/41 нельзя одновременно использовать с внешним JTAG-отладчиком.

В список не входят линии радио, экрана, USB, flash/PSRAM, питания, штатного LED
и загрузочные strapping-пины. GPIO40/41 V4.3 связаны с GPS; GPIO15/16 Paper —
с кварцем 32.768 кГц. Эти выводы нельзя выбирать по примеру другой платы.

**Надпись «3 В» на зуммере не означает, что его можно питать от GPIO.** Для
двухвыводного зуммера используйте подходящий транзисторный драйвер/модуль:
GPIO управляет входом драйвера, зуммер получает питание согласно своему паспорту,
земля общая. Для магнитного/индуктивного излучателя нужна защита от выбросов,
предусмотренная его драйвером. Вход модуля должен принимать логику 3.3 В,
включаться высоким уровнем и не подавать повышенное напряжение на ESP32.
Активный LOW-вход и мостовое подключение этим профилем не поддерживаются.

## Настройка через CLI

Пример для **Paper, GPIO17**, если этот вывод свободен и присутствует в `options`:

```text
schema tone_pin
set tone_pin 17
get tone_pin
caps sound
set sound on
set mute off
set melody 0
sound preview
```

Для других плат выберите вывод из их схемы. `set mute off` явно снимает общую
тишину; пропустите эту команду, если её нужно сохранить. Тогда прослушивание
может вернуть `Error: muted`.

- **Активный зуммер** со встроенным генератором: `set melody 0` — «Пульс».
  Выход выдаёт последовательность HIGH/LOW. Мелодии разных высот такой
  излучатель не воспроизводит как пассивный.
- **Пассивный пьезоизлучатель/совместимый модуль:** `set melody 1`…`30`.
  `melody N` читает название, `set melody N` выбирает, `sound preview` играет.
- `set volume 1`…`10` меняет длительность звучащей части нот/импульсов,
  **не напряжение GPIO**. Реальная громкость зависит от излучателя и драйвера.

Для уведомлений включите звуковой бит каналов. Например, только звук:

```text
schema notify_mode
set notify_mode 2
schema important_notify_mode
set important_notify_mode 2
test
```

Эти команды заменяют выбранные каналы. Если нужен также LED/вибро, используйте
допустимую комбинацию из `schema`: LED=1, звук=2, вибро=4. Paper предоставляет
только внешний звук; переназначение LED и подключение вибрации не добавлены.
`sound preview` проверяет мелодию отдельно от масок, `test` — обычное уведомление.

На **Paper** перерисовка e-paper откладывается до конца мелодии: медленное
обновление панели не должно растягивать звуковой импульс. Радио, CLI и проверка
АКБ продолжают обслуживаться. Пробуждение погасшего экрана кнопкой и выключение
ноды прерывают звук; защита батареи имеет приоритет. Во время длинной мелодии
изображение может оставаться прежним до её окончания.

Отключить выход и сохранить отключение:

```text
set tone_pin -1
get tone_pin
caps sound
```

Текущий звук останавливается, старый GPIO переводится в LOW. При старте ноды
с `tone_pin=-1` выход звука не инициализируется и LED вместо него не выбирается.
`-1` разрешён только у этих четырёх ESP32-профилей; прежние правила nRF52 сохранены.

## Меню, помощник и приложение

В меню платы: **Настройки → Звук и вибро → Выход звука**; у Paper группа
называется **Звук**. Пункт «ВЫКЛ» отключает выход. Назначение через меню
подчиняется тем же ограничениям GPIO, что CLI.

**USB Helper 2.6** показывает выбор `tone_pin`, даже пока `caps sound=0`.
После назначения перечитывает возможности и открывает доступные звуковые
настройки. Старые прошивки сохраняют прежний набор функций.

Для своего приложения сначала проверяйте `schema tone_pin`: при `supported=1`
вывод можно выбирать, даже если `caps sound=0`. После записи перечитайте
`caps sound`, `caps sound_preview`, схемы каналов и значения настроек.
При `tone_pin=-1` `caps sound=0` — ожидаемое состояние. Наличие физического
зуммера не определяется; успешная команда не подтверждает слышимый звук.

## Границы проверки

Релиз проверяется сборками, host-тестами обработчиков GPIO/мелодий, проверками
помощника и совместимости существующих профилей. Это не заменяет испытания
конкретного зуммера, его драйвера и экземпляра платы. В отчёте об испытании
укажите модель/ревизию платы, GPIO, тип и модель излучателя, схему подключения
и результат `sound preview`/`test` после перезагрузки.
