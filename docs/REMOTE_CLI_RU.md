# SmartUI 0.22: удалённая консоль по LoRa

Нода рядом с телефоном может отправить команду другой companion-ноде через
LoRa. Принимающей ноде нужна **SmartUI 0.22** и разрешение для отправителя.
Новый пароль, регистрация и отдельный вход не нужны.

Это отдельная функция прошивки. **USB Helper 2.9 и готовый Local CLI SDK
по-прежнему работают только с локально подключённой нодой.** Для удалённой
консоли требуется приложение с отправкой штатных MeshCore CLI-команд type 3
и показом ответов type 1. Обычное сообщение в чат командой не считается.

## Настройка доступа

Пример: **А** подключена к телефону, **Б** установлена в машине.

1. Установите SmartUI 0.22 на Б.
2. Подключитесь к Б локально через BLE, USB или Wi-Fi. Добавьте А в список
   контактов Б и сверьте полный публичный ключ А.
3. Включите **Remote CLI у контакта А на ноде Б** и сохраните изменение.
   Совместимое приложение может менять этот штатный флаг в настройках контакта.
   Если такого пункта нет, используйте локальные команды из следующего раздела.
4. Подключите телефон к А. Откройте удалённую консоль контакта Б.
5. Отправьте `ver`, затем `get battery`. Дождитесь ответа именно Б.
6. Например, отправьте `set mute on`, затем `get mute`, чтобы проверить результат.

Отправляющей ноде не обязательно иметь 0.22, если её прошивка и приложение
уже поддерживают отправку type 3. **Приём и выполнение на Б требуют 0.22**;
SmartUI 0.21 и старее этого приёма не предоставляют.

Разрешение для Б в списке А действует в обратную сторону. Для взаимного
управления настройте обе принимающие ноды. Разрешение привязано к полной
идентичности контакта; совпадения имени или короткого префикса недостаточно.

## Выдать или отозвать право через локальную консоль

Подставьте полный публичный ключ отправителя: **64 шестнадцатеричных символа**
без пробелов и без угловых скобок. Короткий префикс не принимается.

```text
get remote.cli <FULL_PUBLIC_KEY>
> off

set remote.cli <FULL_PUBLIC_KEY> on
OK

get remote.cli <FULL_PUBLIC_KEY>
> on

set remote.cli <FULL_PUBLIC_KEY> off
OK
```

Команды работают на всех восьми профилях через локальный CMD66 по BLE,
USB-companion или Wi-Fi, а также через текстовую сервисную USB-консоль.
Контакт должен уже существовать. `OK` после изменения означает успешное
сохранение права; при ошибке записи изменение откатывается. Остальные биты
разрешений контакта сохраняются.

Эти команды **нельзя выполнить по LoRa**, даже имея Remote CLI. Так удалённая
нода не может выдать доступ следующему контакту. Каталог Helper 2.9 и готовые
Local CLI SDK новые команды выдачи прав не пропускают; используйте локальную
консоль приложения с прямой отправкой CMD66 либо сервисную USB-консоль.

`Error: contact not found` означает отсутствие полного ключа в контактах
получателя. Ошибка аргумента требует проверить ключ и `on`/`off`.
`readonly`, `busy` и `storage` — отказ записи, а не подтверждённое сохранение.
При тайм-ауте сначала перечитайте право; автоматически повторять запись нельзя.

## Какие команды доступны

Используется тот же набор чтения и управления, что в
[справочнике локальной консоли](CONSOLE_COMMANDS_RU.md), с ограничениями
[конкретной платы](CLI_BOARD_MATRIX_RU.md). Например:

| Команда | Назначение |
| --- | --- |
| `ver`, `board`, `get battery` | Версия, плата, состояние питания |
| `get mute`, `set mute on`, `set mute off` | Проверить, включить или выключить общую тишину |
| `get volume`, `set volume 7` | Прочитать или изменить громкость, если поддерживается |
| `get radio`, `ui radio` | Прочитать радиопараметры |
| `get connection`, `ui mode status`, `ui wifi status` | Прочитать состояние локального подключения |
| `reboot` | Принудительно перезапустить без сохранения RAM |

Права Remote CLI дают доступ и к чувствительным командам, например чтению
BLE PIN. Выдавайте их только доверенной идентичности. Изменение радиопараметров
может сразу лишить вас связи; отсутствие ответа не означает отказ изменения.
Наличие команды не добавляет отсутствующий дисплей, GPS, зуммер или усилитель.

Следующие группы по LoRa возвращают **`Error: local only`**:

| Команды | Причина |
| --- | --- |
| `set connection …`, `ui mode …`, кроме точной `ui mode status` | Смена локального транспорта требует локальной сессии |
| `ui wifi …`, кроме точной `ui wifi status` | Подготовка и сохранение Wi-Fi принадлежат локальной сессии |
| `ui adc …`, `adc …`, `set adc …`, `set adc.multiplier …` | Сервис ADC и его предварительные расчёты выполняются локально; запись требует USB |
| `get remote.cli …`, `set remote.cli …` | Права контактов проверяются и меняются локально |
| `api …`, `settings …`, `wifi …` | Другие сервисные входы не являются удалённым интерфейсом |

Чтение сохранённого коэффициента через обычный `get` не требует запуска
сервиса ADC. Аппаратные ограничения, ошибки хранилища и проверки допустимых
значений продолжают действовать для остальных команд.

Изменение обычных настроек, в том числе по LoRa, может аннулировать ранее
подготовленный локальный preview ADC. Перед применением рассчитайте его заново.

### Принудительный `reboot`

Полученная допустимая команда `reboot` от разрешённого контакта перезапускает
ноду без сохранения и ожидания `readonly`/`busy`/ошибки хранилища. Несохранённые
изменения в RAM могут потеряться. Команда не форматирует файлы и не выполняет
заводской сброс.

Нода может перезапуститься раньше передачи ответа. Тайм-аут ожидаем:
дождитесь возвращения ноды и проверьте её состояние. Не отправляйте `reboot`
автоматически снова. При полностью зависшем CPU, остановленной обработке
пакетов или недоступной радиосвязи CLI не сможет доставить и выполнить команду.
Меню, двоичный `CMD_REBOOT` и выключение сохраняют прежние проверки сохранения.

## Протокол для приложения

1. Локальное приложение передаёт своей ноде штатный **CMD2** для контакта
   назначения с текстовым типом **`TXT_TYPE_CLI_COMMAND = 3`**.
2. MeshCore доставляет зашифрованный пакет целевому контакту. SmartUI проверяет
   бит **`0x10`** (`isRemoteCLIAllowed()`) в собственной записи отправителя.
3. Ответ возвращается штатным **`TXT_TYPE_CLI_DATA = 1`**. Приложение получает
   его через обычный путь сообщений companion-протокола.

**CMD66/RESP29 по LoRa не передаются.** Они обслуживают локальную консоль.
Custom variable `remote_cli:1` объявляет поддержку приёма на подключённой
ноде; наличие `smartui_cli:1` само по себе удалённую поддержку не обещает.
Этот локальный discovery не сообщает возможности другого контакта.

Тело команды и тело ответа — не более **156 байт UTF-8** каждое. Необязательный
префикс корреляции — два ASCII символа `[A-Za-z0-9]` и `|`; например:

```text
a9|set mute on
a9|OK
```

Префикс занимает отдельные три байта и возвращается без изменения.
Управляющие байты, переводы строк, DEL, некорректный UTF-8, пустая команда
и дополнительные `|` не допускаются. Разбиения на страницы и multipart нет.
Слишком длинный ответ отклоняется, а не выдаётся как успешная усечённая запись.

Для одного контакта отправляйте одну команду за раз. `RESP_SENT` подтверждает
постановку исходящего пакета в очередь, **не выполнение команды**. Ожидайте
ответ нужного контакта, типа и префикса; после изменения читайте состояние
обратно. Приложение не должно автоматически повторять мутации при тайм-ауте.

| Ответ | Значение |
| --- | --- |
| `Error: denied` | У распознанного отправителя нет Remote CLI |
| `Error: replay` | Timestamp не новее уже принятого для этой идентичности в текущем запуске |
| `Error: local only` | Команда допускается только локально |
| `Error: command too long` / `Error: invalid command` / `Error: invalid prefix` | Запрос не прошёл проверку формата |
| `Error: response too long` / `Error: invalid response` | Ответ не помещается или не соответствует текстовому формату |
| `Unknown command` | Такой команды нет |

Ошибки самой команды (`unsupported`, `readonly`, `busy`, `storage` и другие)
сохраняют обычный формат. Неизвестный контакт не получает право исполнения;
наличие ответа для любого недопустимого или недоставленного пакета не гарантируется.

## Повторы и границы защиты

Remote CLI использует штатное шифрование и MAC MeshCore. Этот выпуск не меняет
криптографический протокол и не добавляет ему новую схему аутентификации.
Разрешение телеметрии, включая её `ALLOW_ALL`, не даёт права управления.

Для каждого контакта в RAM хранится наибольший принятый timestamp команды.
Следующая команда должна иметь строго больший timestamp. Одинаковый текст
с новым timestamp — новая команда, а не повтор прежней операции. Обеспечьте
возрастание timestamp при отправке нескольких команд, в том числе в одну секунду.

Эта защита действует **только в текущем запуске**. После перезагрузки ноды
старая команда может быть принята повторно. Постоянного журнала исполнений
и гарантии «строго один раз» нет. Поэтому тайм-аут означает неизвестный
результат, а не разрешение автоматически повторить изменение.

Проверки на компьютере не заменяют испытания реальной радиосвязи. Поддержка
удалённой консоли не доказывает устранение всех причин зависания или потери TX.
