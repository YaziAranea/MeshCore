# SmartUI 0.20: переход на MeshCore 1.18.0

## Происхождение исходников

SmartUI 0.20 объединяет исправленный SmartUI 0.19 (`d866d409`) с официальным
[Companion Firmware v1.18.0](https://github.com/meshcore-dev/MeshCore/releases/tag/companion-v1.18.0).
Официальный commit: `81dbae592ffad40b4212bc0b37e82b38da08f4bc`.
Объект аннотированного тега имеет другой SHA; в манифесте указывается именно commit.
Слияние сохраняет историю обеих веток, а не только меняет строку версии.

Ранее перенесённые механизмы PowerSaving происходят из IoTThinks/MeshCore,
`a27e78e4da1389055b6dd16ce473112d25c8a5cd`. Это отдельное происхождение
дополнений, не SHA официального MeshCore 1.18.0.

## Границы совместимости

| Область | Решение SmartUI |
|---|---|
| Ядро и companion-протокол | Официальная база 1.18.0; локальные CMD66/RESP29 и компактный CLI сохранены |
| Настройки | Сохранены имена существующих полей и проверяемая запись через временную и резервную копии; новые поля получают значения по умолчанию |
| FEM | Меню, CLI и сохранённые настройки используют прежний единый источник данных; перенос upstream на dynamic prefs не создаёт второй независимый переключатель |
| AGC | Сохранён один планировщик SmartUI с проверками занятости радио и отправки ответа; второй upstream-планировщик не запускается |
| Подключение | Сохранён явный выбор BLE, USB или Wi-Fi и защищённая процедура смены; одновременный доступ нескольких управляющих клиентов не включён |
| Команды через LoRa | Текстовый тип 3 передаётся приложению; удалённое выполнение CLI на самой ноде не включено |
| Интерфейс | Сохранены SmartUI, ручная страница BLE PIN, клавиатура, уведомления и исправление геометрии T114; экранная карусель upstream не подменяет SmartUI |
| Без экрана | Отдельный ProMicro/FakeTec RA62 headless-профиль не инициализирует дисплей, сохраняя обслуживание уведомлений, питания и настроек |
| Старые расширения | API201, синхронизация прочтения и Phone GPS не включены |

Это производная прошивка SmartUI на официальной базе, с перечисленными отличиями
поведения. Номер ядра сам по себе не гарантирует наличие любой функции stock UI.
Приложения должны проверять `ui hello`, `caps` и `schema`.

## Сохранность данных

Обычное обновление UF2 не требует стирания. На ESP32 для сохранения данных нужен
`update.bin` своей платы по адресу `0x10000` с совместимой таблицей разделов.
`merged.bin` содержит подготовленную пустую файловую систему и заменяет данные.

Миграционные проверки используют реальные сериализаторы и проверяют копирование
настроек, привязку вложенных объектов к новому владельцу, сохранение и повторную
загрузку. Отдельно проверяются границы dynamic-полей: неправильный ключ и маленький
буфер не должны повреждать память. При ошибке записи настройки не объявляются
сохранёнными. Повреждённая identity не заменяется новой молча.

## Проверки перед публикацией

Публичная сборка проходит компиляцию всех восьми профилей, проверки UF2/BIN,
native/host-тесты, проверку стека ARM, симуляции UI и браузерные тесты Helper.
Новый headless UF2 входит в те же проверки исходного commit и контрольных сумм.
Отдельное ревью проверяет изменения хранения, радио, питания, протокола и Helper.

Встроенный source marker, `RELEASE-MANIFEST.json` и SHA-256 связывают комплект
с одним проверенным commit. Результаты сборок и host-тестов не заменяют испытания
на физических устройствах. Проверки конкретного опубликованного комплекта
указываются в [примечаниях к выпуску](../RELEASE_NOTES_SmartUI_0.20_RU.md).

## Что исправил независимый аудит переноса

- Сериализатор dynamic prefs: ограничены длины ключей и выходного буфера;
  неверная структура JSON, повтор объекта скалярным полем и лишние запятые
  больше не перенаправляют запись в предыдущий вложенный объект.
- Копирование `NodePrefs`: вложенные настройки привязываются к новому владельцу;
  признак изменений сбрасывается только после успешного сохранения.
- Ответы Companion: длины проверяются до чтения идентификаторов и полей;
  проверены короткие и предельные пакеты, включая ответы входа.
- Значения TX delay проверяются на конечность; мощность TX сохраняет знаковый
  тип во всём интерфейсе настроек. Общий радио-CLI отклоняет `NaN`, бесконечность,
  пустые числа и посторонние символы без изменения настроек.
- Профиль Heltec V4 R8: устранено дублирующее объявление метода LNA после слияния.
- Room server: сохранено применение настроек FEM при запуске на платах,
  использующих прежний интерфейс управления усилителем.
- Sensor: проверяются длины запросов и полных скалярных записей подписки;
  некорректная подписка сохраняет прежнее состояние. Для отправки телеметрии
  зарезервированы все восемь байт заголовка. Исправлен формат влажности LPP
  согласно CayenneLPP 1.6.1: один байт, шаг 0,5%.

Для ошибок памяти и разбора добавлены проверки реального кода с ASan и UBSan,
включая сборку с `-Ofast`. Helper, SDK, управление подключением, радио и питание
проверены отдельными ревью после реализации. Показ PIN требует явного запроса,
не меняет настройки и не добавляет код в журнал Helper.
