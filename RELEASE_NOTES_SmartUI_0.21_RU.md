# Smart UI 0.21 — исправления хранения и запуска nRF52

**Рекомендуем обновление T096, T114 и ProMicro/FakeTec.** Исправлены ошибки
доступа к flash-памяти: конфликт одновременных операций, обращение за границы
хранилища при повреждённых данных и первый запуск с полностью пустым хранилищем.
На всех платах добавлен принудительный перезапуск командой `reboot` в CLI,
даже если сохранение данных не работает.

Это отдельный выпуск. SmartUI 0.20 остаётся доступен. База — **MeshCore 1.18.0**;
USB Helper остаётся **2.9**, с автоприменением, консолью и макросами.
Чтобы получить исправления прошивки, установите файл **0.21** своей платы.
Замена одного HTML-файла Helper их не добавляет.

## Что исправлено

- **Запись настроек и контактов больше не конфликтует с сохранением
  BLE-сопряжения.** На nRF52 эти операции используют общий буфер flash.
  Раньше две файловые системы защищали его разными блокировками и могли
  одновременно менять. Теперь блокировка одна для обеих областей.
- **Повреждённый файл не разрешает чтение за границами хранилища.** Драйвер
  проверяет номер блока, смещение и длину до вычисления адреса. Неверная
  ссылка возвращает ошибку, вместо обращения к постороннему адресу памяти,
  которое могло привести к аварийному перезапуску во время загрузки.
- **Пустое хранилище готовится автоматически и безопасно.** Ранее полностью
  пустая область контактов могла остановить первый запуск. Теперь прошивка
  создаёт файловую систему, только если прочитала всю область и убедилась,
  что каждый байт равен `0xFF`.
- **Ошибка открытия существующего хранилища не запускает очистку.** Убрано
  прежнее автоматическое форматирование области настроек при любом отказе
  открытия. Если есть старые данные или ошибка чтения, прошивка сохраняет
  область для диагностики. Разметка flash и форматы файлов не менялись.

Исправления драйвера хранения относятся ко всем четырём nRF52-профилям: **T096 FEM ON, T114,
ProMicro RA62 с OLED и ProMicro/FakeTec RA62 без экрана**. Четыре ESP32-профиля
пересобраны в общем выпуске; эти изменения драйвера flash на них не действуют.

## Перезапуск через CLI без ожидания сохранения

Если нода отвечает на CLI, но не перезагружается из-за ошибки хранения,
отправьте отдельной командой:

```text
reboot
```

В 0.21 это **принудительный перезапуск на всех восьми профилях**, включая
ESP32 и ProMicro/FakeTec без экрана. Команда не ждёт сохранения контактов
и не блокируется состояниями `readonly`, `busy` или ошибкой хранилища.
Требуется доступ к локальной консоли ноды: сервисный USB либо Companion CLI
через установленное BLE/USB/Wi-Fi-соединение.

**Несохранённые изменения в оперативной памяти могут потеряться.** Это не
сброс настроек и не форматирование: уже сохранённые файлы не очищаются.
Соединение отключится; ответ `OK` может не успеть прийти. После повторного
подключения проверьте, что нода действительно перезапустилась.

Перезагрузка из меню, штатная двоичная команда Companion `CMD_REBOOT`
и выключение по-прежнему сначала сохраняют изменения. Полностью зависшую
ноду, которая не обрабатывает команды, CLI перезапустить не сможет.
Поле команд Helper 2.9 и готовые SDK `reboot` не отправляют; используйте
CLI приложения с поддержкой этой команды или сервисный USB-терминал.

## Как обновиться

1. Сохраните нужные контакты и идентичность ноды средствами приложения.
   Перед обновлением nRF52 проверьте число контактов: ограничение — **200**.
2. Скачайте файл своей платы и контрольные суммы из этого выпуска.
3. **T096, T114, ProMicro/FakeTec:** скопируйте обычный UF2 на диск загрузчика.
   Предварительный `FLASH_ERASE` не требуется.
4. **ESP32:** для работающей совместимой установки используйте `update.bin`
   по адресу `0x10000`, без Erase. `merged.bin` по адресу `0x0` предназначен
   для чистой установки: он удаляет прежние данные даже без отдельного Erase.
5. После запуска проверьте контакты, радиопараметры и подключение.
   Сохраняются прежние BLE PIN и выбранный транспорт.

**Если на nRF52 осталось больше 200 контактов, сохранятся первые 200 записей
в порядке файла ноды; остальные будут удалены.** Это прежнее правило
исправленного 0.20. Чтобы выбрать конкретные контакты, сократите список до
обновления. На ESP32 предел остаётся **350**.

Обычное обновление сохраняет пригодные прежние данные. Оно не восстанавливает
уже повреждённые файлы. `FLASH_ERASE_nrf52_softdevice_v6.uf2` форматирует
хранилище и удаляет идентичность, настройки, контакты, каналы и BLE-сопряжения;
это отдельная разрушительная операция, а не обязательный шаг обновления.

## Какой файл выбрать

| Плата | Файл для обычного обновления |
|---|---|
| Heltec T096 FEM ON | `T096_UI_0.21.uf2` |
| Heltec T114 | `T114_UI_0.21.uf2` |
| ProMicro nRF52840 + RA62 с OLED | `ProMicro_RA62_UI_0.21.uf2` |
| ProMicro / FakeTec V4 + HT-RA62 без дисплея | `ProMicro_FakeTec_RA62_Headless_UI_0.21.uf2` |
| Heltec V3 | `Heltec_V3_UI_0.21-update.bin` |
| Heltec V4.3 OLED FEM ON | `Heltec_V4.3_UI_0.21-update.bin` |
| Heltec V4 R8 OLED FEM ON | `Heltec_V4_R8_UI_0.21-update.bin` |
| Wireless Paper FULL | `Paper_UI_0.21-update.bin` |

Для FakeTec требуется стандартная распайка nRF52840 + HT-RA62/TCXO.
На headless-ноде без прежних настроек BLE PIN — `123456`; после обновления
остаётся прежний PIN. Неизвестный код читается в Helper по USB:
**«Подключить ноду» → «Расширенное» → «Подключение» → «Показать PIN»**.

В выпуске восемь профилей, двенадцать образов прошивок и двадцать файлов
вложений. Общий `RELEASE-MANIFEST.json` указывает исходный commit и SHA-256.
`SHA256SUMS.txt` относится к UF2, `SHA256SUMS-ESP32.txt` — к BIN.

## Проверки и границы исправлений

Автоматические проверки охватывают существующую и полностью пустую файловые
системы, ошибки чтения и форматирования, неверные адреса в повреждённых файлах
и одновременный доступ двух файловых систем к общему буферу flash. Сохранены
проверки контактов, миграции лимита, восстановления после прерванной записи,
CLI, Helper и сборок всех восьми профилей.

Проверки на компьютере и сборка прошивок не заменяют испытания физических
плат. Причина конкретного случая с повторяющимся `Loading…` на T114 не
подтверждена логом устройства; выпуск исправляет найденные ошибки, но не
объявляет устранёнными все возможные причины перезапуска или остановки TX.
Если симптом повторится, сохраните версию и SHA-256 UF2, видео и доступный
загрузочный лог до очистки. Приватный ключ и BLE PIN публично не отправляйте.
