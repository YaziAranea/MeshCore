# Smart UI 0.15 — настраиваем ноду из консоли приложения

Теперь основные настройки своей ноды можно менять короткими командами прямо
в приложении с поддержкой локальной «Консоли радио» MeshCore. Не нужно искать
каждый пункт на маленьком экране. Настройки общие: изменение из консоли
сохраняется так же, как изменение в меню ноды.

## Что добавили

1. **Громкость и вибро.** `get volume`, `set volume 7`, `set vibration on`.
2. **Мелодии.** `melodies` показывает текущую и максимальный номер; `melody 2`
   читает название; `set melody 2` выбирает; `test notification` проверяет
   уведомление с текущими настройками звука, вибро и LED.
3. **FEM.** Отдельные `get/set fem.lna` и `get/set fem.pa` на поддерживаемых
   платах. Включение отсутствующего оборудования не имитируется.
4. **ADC.** Привычные `get adc.multiplier` и `set adc.multiplier КОЭФФИЦИЕНТ`.
   Сохранён расчёт по мультиметру, отдельное применение и заводской сброс.
   Проверки диапазона и ошибки памяти не обходятся.
5. **Мощность и радио.** В выпуск включены команды оригинального MeshCore:
   `get tx`, `set tx`, чтение/настройка радио, имя ноды, PIN, часовой пояс и
   другие поддержанные параметры. Смена мощности теперь отклоняется, если
   радио занято, до изменения сохранённых настроек.
6. **Автоанонс, LED, GPS, AGC.** Короткие команды используют те же параметры,
   что экранное меню. Например, `set advert 60` — анонс раз в час.
7. **Справка.** `help` показывает темы; `help sound`, `help adc`, `help radio`
   и другие разделы объясняют команды. Длинные темы разделены на короткие
   страницы, чтобы ответ не обрезался.
8. **USB Helper 1.9.** В «Для разработчика» добавлены справка, короткие команды
   и поддержанные команды MeshCore, включая TX. Результат разрешённых чтений
   виден в интерфейсе. Изменения требуют подтверждения; ADC и Wi-Fi настраиваются
   отдельными формами. Прежние функции и пресеты городов сохранены.

## Как попробовать

Обновите ноду, подключите к приложению и откройте консоль **своего компаньона**.
Приложение должно поддерживать локальный CLI (CMD66/RESP29). Отправляйте по одной
команде, ожидая ответа:

```text
ver
help
get volume
set volume 7
get volume
```

`get` читает; `set` меняет и сохраняет. Отдельный `save` не нужен. Для
переключателей используйте `on`/`off` или `1`/`0`. Возможности платы проверяются
командами `caps`, например `caps vibration` или `caps fem.lna`.

Если пропал ответ, не повторяйте запись автоматически: переподключитесь и
прочитайте состояние. `Error: unsupported` означает неподдерживаемую функцию;
`readonly`/`storage` требуют диагностики, а не очистки памяти.

[Полная русская справка с примерами](https://github.com/YaziAranea/MeshCore/blob/smartui-0.15/docs/CONSOLE_COMMANDS_RU.md)
· [Инструкция помощника](https://github.com/YaziAranea/MeshCore/blob/smartui-0.15/tools/usb-helper/README_RU.md)
· [Протокол и SDK для разработчиков](https://github.com/YaziAranea/MeshCore/blob/smartui-0.15/docs/SMARTUI_CLI_RU.md).

Справка также вложена в ZIP помощника и Developer Kit: её можно читать без
интернета. В обычном Serial-терминале остаётся прежний синтаксис `settings …`;
короткие `get/set` из этого выпуска относятся к консоли приложения-компаньона.

## Важное про ADC и оборудование

1. Из ретрансляторной CLI взяты знакомые имена ADC, а не неограниченная запись
   числа. Коэффициент проверяется по диапазону конкретной платы; ноль не
   означает сброс, для сброса есть `adc reset`.
2. Прямой ввод проверенного коэффициента не требует предварительного замера
   без USB. Для расчёта по мультиметру ProMicro нужен свежий замер от АКБ:
   USB может искажать измерение. Не копируйте коэффициент чужой платы.
3. Сервисное окно до двух минут осталось только для локального USB с надёжным
   подтверждением питания. Оно не исправляет физически разряженный аккумулятор
   и не является обычным режимом работы. Пороги защиты **3,2/2,7 В** не менялись.
4. `sound.bridge` — электрический мостовой выход для подходящего плавающего
   пьезоизлучателя между штатными выводами. Это не сетевой мост; выход нельзя
   соединять с землёй. FEM/GPS/вибро требуют подходящей платы и подключения.

## Какой файл скачать

| Плата | Файлы |
| --- | --- |
| T096 FEM ON | `T096_UI_0.15.uf2` |
| T114 | `T114_UI_0.15.uf2` |
| ProMicro RA62 | `ProMicro_RA62_UI_0.15.uf2` |
| Heltec V3 OLED | `Heltec_V3_UI_0.15-update.bin` / `Heltec_V3_UI_0.15-merged.bin` |
| Heltec V4.3 OLED R2 | `Heltec_V4.3_UI_0.15-update.bin` / `Heltec_V4.3_UI_0.15-merged.bin` |
| Wireless Paper | `Paper_UI_0.15-update.bin` / `Paper_UI_0.15-merged.bin` |
| Heltec V4 R8 OLED | `Heltec_V4_R8_UI_0.15-update.bin` / `Heltec_V4_R8_UI_0.15-merged.bin` |

UF2 обновляется поверх, без `FLASH_ERASE`. Работающую совместимую ESP32-ноду
обновляйте `update.bin` по адресу **0x10000**, без очистки.

**Любой ESP32 `merged.bin` предназначен для чистой установки по 0x00000 и
перезаписывает identity, контакты и настройки даже без Erase Flash.**
V4.3 R2 и V4 R8 не взаимозаменяемы. Цветной TFT R8 в этот набор не входит.

Полный комплект: `SmartUI_0.15_all-boards.zip`. Отдельно доступны
`SmartUI_USB_Helper_1.9.html`, ZIP помощника и `SmartUI_Developer_Kit_0.15.zip`.
Все 11 прошивок семи плат связаны с одним исходным commit в
`RELEASE-MANIFEST.json`; всего 19 файлов выпуска. Есть списки SHA-256.

## Совместимость и границы проверки

База осталась **MeshCore 1.17.1 / PowerSaving**. Companion-протокол — **14**;
расширенные короткие команды обнаруживаются по `console=1`, имена оригинального
MeshCore — по `meshcore=1` в `ui hello`. Это не полное слияние upstream dev.

Прежние `ui …` сохранены. API201, события и синхронизация прочтения из архивной
0.11 не возвращались. Выполнение удалённых команд через LoRa не включалось.
Wi-Fi/TCP остаётся портом 5000 без отдельной аутентификации/TLS: только
доверенная локальная сеть, без проброса порта в интернет. Приватная ветка не
изменялась; публичный 0.14 остаётся отдельным выпуском для отката.

Публикация проходит общий CI: сборки семи плат, проверки UF2/BIN/хранилища,
локальные команды и их ошибки, SDK, интерфейс помощника, native-тесты и
дисплейные симуляции с реальными шрифтами. Проверяются `-O1` и nRF52 `-Ofast`,
границы ответа, сохранение с откатом, отсутствие записи при отказе и
совместимость старых команд.

Это программные проверки и имитация подключений. Проверка всех физических
плат, зуммеров, FEM, схем питания и приёма в эфире не заявляется.
